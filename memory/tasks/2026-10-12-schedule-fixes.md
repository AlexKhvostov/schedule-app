## Промежуточные результаты

- В occupancy уже сохраняются member_id, kind_id, slot_date, half, level и снимок tables. Метка/цвета/Discord/игровой ник читаются соединением таблиц в load_month_schedule; это подтверждено кодом миграции и клиентского слоя.
- По новому решению Алексея отсутствие букв — отсутствие кисти; прежнее замечание аудита №4 снимается. Пустой профиль допускается, но новые слоты без букв не создаются. Существующие строки не удаляются автоматически.
- Общая промежуточная сетка не внедряется в этой задаче. Рабочая рекомендация агента: сначала измерить нагрузку; дополнительная копия требует обновления при изменении слотов и пользовательских атрибутов. Materialized view PostgreSQL хранит результат и требует REFRESH; свежесть не гарантирована автоматически: [официальная документация](https://www.postgresql.org/docs/current/rules-materializedviews.html).
- Найден PostgreSQL 12 вне PATH. Поднят отдельный кластер на 127.0.0.1:55439, без связи с Working. Все 68 миграций загружены в транзакциях с изолированной эмуляцией Supabase auth/default grants/publication; cron/net отключены, для старого PostgreSQL кавычками оформлен alias value в временных копиях двух существующих read-model функций. Исходные миграции репозитория не менялись.
- Существующие SQL contracts, filter limits, player limits, table presets прошли. Полный Supabase 15 reset/lint остаётся CI-шлюзом, поскольку локально нет Docker/Supabase CLI.

## Итог реализации

- [Состояние месяца](../../apps/web/src/v2/schedule/scheduleMonthState.ts) содержит одну подтверждённую основу и слои незавершённых правок отдельных клеток; запись выполняется последовательно. [gridEdits](../../apps/web/src/schedule/gridEdits.ts) — единый алгоритм разницы и применения клеток, старый seatDiffs сохранён как адаптер этого алгоритма, а не вторая реализация.
- [Загрузка и realtime](../../apps/web/src/v2/schedule/useScheduleMonth.ts) не пропускают события по совпадению владельца. Общий таймер 250 мс объединяет события и завершение очереди, чтение не применяется поверх незавершённых правок. Чужой месяц и старое поколение ответа не принимаются.
- [Подтверждение диапазона](../../apps/web/src/v2/schedule/useScheduleMutations.ts) использует исходный снимок жеста только для разницы затронутых клеток; дата/месяц проверяются. ID кисти фиксируется в момент действия. Результат старого месяца не меняет интерфейс нового. Новый RPC вызывается один раз, уведомление — только после успеха.
- [Миграция](../../supabase/migrations/20261012010000_atomic_schedule_edit.sql) проверяет ожидаемые чужие member_id под FOR UPDATE, валидирует диапазон/время/столы, требует полного выполнения всех шагов и делегирует существующие права. Ошибка отменяет весь диапазон и события. Отсутствие RPC не запускает опасный fallback.
- Новые тексты ошибки/повтора/конфликта добавлены одновременно в RU и EN. Обновлены docs/decisions.md, current-state.md, schedule-ux.md, database.md, code-architecture.md, operations.md и work-log.md. Старый отчёт аудита помечен историческим; пункт №4 снят решением пользователя.
