## Реализация

- [load_month_roster](../../supabase/migrations/20261104164056_compact_month_roster.sql) проверяет schedule, использует существующий priority_slice_source и прежний schedule_player_directory. На человека рейтинга передаются только memberId/core/score/excluded; исходные entries, месяцы и промежуточные суммы не передаются. Нового серверного кэша/формулы нет.
- У рейтинга и справочника независимые хеши содержимого. Сравнение происходит после проверки прав; совпавший массив заменяется null, пустой список остаётся[]. Дата/период/вид/группа/статус/время расчёта возвращаются всегда. Это сокращает трафик, но штатный запрос и проверка базы каждые30секунд сохраняются. Время/трафик на рабочем сайте не измерялись, поскольку выпуска нет.
- [data/roster.ts](../../apps/web/src/data/roster.ts) объединяет параллельные чтения и хранит до8 снимков для текущего экрана/аккаунта. Ключ включает период/вид/группу/нормализованные лимиты. Условный ответ принимается только при совпадении сохранённой версии; ошибка не превращается в пустую очередь. Неизменённые массивы/объекты переиспользуются без лишней сортировки по таймеру.
- [rosterRefresh](../../apps/web/src/data/rosterRefresh.ts) объединяет события за100мс. Во время запроса обычная проверка не создаёт второй запрос, сигнал записи ставит одну повторную проверку. [useRosterSource](../../apps/web/src/v2/schedule/useRosterSource.ts) отменяет применение ответов старого контекста и прекращает сетевой опрос при hidden/closed; возврат видимости обновляет данные. Persistent storage с данными рейтинга не добавлялся.
- [orderRosterRows](../../apps/web/src/schedule/roster.ts) использует прежний компаратор, получая готовые core/score/excluded. Для отсутствующей карточки прежний fallback сохранён;250 не получает Core50–100. Фильтры состава/часы/исторические строки не менялись.
