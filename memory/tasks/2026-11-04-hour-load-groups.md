## Проверки и ограничения

- Web: typecheck, lint, build и bundle:check прошли; 44 файла / 199 unit-тестов, До уточнения сворачивания полный Playwright — 58 passed и 1 штатный skip реальной Discord-сессии. После уточнения: полный набор дал 58 passed, 1 skip и одну ошибку тестового кода (лишняя ссылка deadPanel в чужом сценарии диапазонов). Ошибка удалена, typecheck и целевой повтор этого сценария прошли: всего 59 уникальных успешных E2E. Код приложения по результатам повтора не менялся. Vitest выполнен с threads/2 workers; первоначальный запуск с forks завершил тесты, но Windows выдал EPERM при остановке процесса, поэтому выполнен чистый повтор с exit 0.
- Изолированный локальный Supabase PG15: reset всех 78 миграций с seed, все 13 SQL-наборов и database lint успешны. Новый контракт проверяет права администратора/игрока/anon, N50/E50/N100, параллельные записи, валидацию и неизменность остальных настроек.
- Security advisors: восемь прежних предупреждений function_search_path_mutable, новых предупреждений для hour_load нет. Это не аудит и не исправление всей прежней схемы.
- IAB: сохранение N50, независимость E50, одинаковые три селектора; Playwright: обе темы, RU/EN, мобильная ширина, точная геометрия скрытых часов и уровней, подсказка при переходе N50 → N100 → E50.
- Облачный проект и реальная авторизованная многопользовательская среда не менялись. До выпуска клиента применить миграцию палитры и затем [миграцию нагрузки](../../supabase/migrations/20261104101829_schedule_hour_load.sql), выполнить smoke по [operations](../../docs/operations.md). - Логика ёмкости и мёртвого времени сохранена; в них заменён общий блок выбора пары. Новый контракт хранения относится к нагрузке по часам.
