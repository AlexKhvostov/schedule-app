## Цель

По сообщению Алексея существующая импортированная дистанция не сохраняется при замене последнего ненулевого значения на0. Требуется дать возможность исключить турниры, сохранив нулевую запись либо удалив её. Рабочий выбор: сохранить логическую запись с нулевой суммой, ID и аудитом; не создавать отдельную операцию удаления. Пользовательские данные со скриншота не менять в ходе проверки.

## Уточнение пользователя и результат

Алексей разрешил выбирать при импорте, сохранять ручные правки или перезаписывать. Общий переключатель реализован в обеих формах, по умолчанию OFF и сбрасывается при новом файле. OFF защищает всю ручную запись, включая отсутствующие лимиты. ON заменяет только явно указанные лимиты, включая 0. Комментарии и отсутствующие в файле лимиты остаются. Пустое количество в обоих форматах CSV пропускается; явный 0 передаётся. Защита сохраняется после разрешённой перезаписи. Обычные числовые дубли по-прежнему пропускаются.

Нулевая запись сохраняет ID, происхождение и комментарий. В таблице используется прежний прочерк для нуля, в редакторе итог 0; запись видна в фильтре наличия дистанции и доступна для повторного изменения. Новая пустая запись запрещена.

Миграция [20261107130531](../../supabase/migrations/20261107130531_allow_zero_distance_update.sql) добавляет manual_override, отмечает прежние ручные изменения без изменения времён аудита и сохраняет старые сигнатуры RPC. Редактор и импорт блокируют запись перед изменением. Права staff/root сохранены.
