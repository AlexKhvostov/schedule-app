# Доступ к Dashboard через роли

Обновлено: 2026-11-06 03:34 Europe/Minsk. Готово локально.

Цель Алексея: выдавать доступ к разделу Dashboard через существующий редактор ролей.

| Этап | Статус | Критерий завершения |
|---|---|---|
| Анализ существующих прав | Готово | Каталог, назначение роли, серверный контекст и маршрутизация согласованы |
| Реализация | Готово | Право dashboard, флажок в ролях, скрытие меню и запрет прямой ссылки без права |
| Проверки | Готово | Выдача/отзыв, обычный участник/root/неактивный; unit/E2E/SQL и сборка |
| Документы | Готово | Описаны включение, границы защиты, результаты |

Рабочее решение: отдельное право dashboard, без автоматической выдачи существующим ролям. Root сохраняет доступ по общей модели, но только с active-профилем. Членство/права берутся из существующего серверного member_access_context. Рабочие роли и назначения сейчас не меняем; миграция и проверки локальные. Публичный legacy PHP API этой настройкой не защищается, production-guard аналитики сохраняется.


Реализовано: миграция 20261106002512_dashboard_role_permission.sql добавляет dashboard в каталог; общий canAccessDashboard используется меню/маршрутом/рендером; право не добавляется автоматически в Demo menuPermissions. MembersRoleSettings локализует название в RU/EN и сохраняет обычным механизмом роли. Отзыв применяется при обновлении страницы/входе, как остальные права оболочки, отдельный мгновенный отзыв открытой вкладки не добавлен.
