Основные файлы: [scheduleConfiguration.ts](../../apps/web/src/data/scheduleConfiguration.ts), [scheduleSyncSettings.ts](../../apps/web/src/data/scheduleSyncSettings.ts), [ScheduleSyncSettingsEditor.tsx](../../apps/web/src/v2/ScheduleSyncSettingsEditor.tsx), [priorityUpdates.ts](../../apps/web/src/data/priorityUpdates.ts). Существующие загрузчики, V2Admin/V2Shell/LivePriorities/useRosterSource, локали и тесты обновлены.

Ревью database выявило initial HTTP→subscribe gap: исправлен первичной инвалидацией после SUBSCRIBED, покрыт race-test. После async getAppAccount используется текущий синхронный ключ владельца кеша. Поздние ответы предыдущего аккаунта отвергаются. Кеш общий только внутри вкладки, серверные права им не определяются.

Ограничение: ручная операция обновления приоритетов теоретически может совпасть с фоновым чтением; обычные event/focus чтения объединяются 100мс координатором, регулярного SQL-таймера нет. Основному агенту передано замечание сузить документационную гарантию одного запроса до сетки и общего пакета конфигурации.

Следующий шаг: интеграционные E2E, сверка документации и тестовый деплой основным агентом. Коммит, push и изменения remote DB эта подзадача не выполняла.
