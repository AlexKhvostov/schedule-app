- member_has_permission для этой карточки: profile/schedule/priorities=true; административные права=false. Заявок нет.

## Проверка пустого фона

В IAB открыта локальная страница с текущими index.css/v2.css и структурой V2JoinGate, без реальных аккаунтов и API. Сначала дерево страницы содержит форму, но на снимке виден только фон. Вычисленные стили: stage::before position=absolute/z-index=0; gate position=static/z-index=auto. В том же примере с единственным дополнением `.v2-gate { position: relative; z-index: 1 }` форма становится видна. Это воспроизведение дефекта слоёв текущего кода, не сеанс браузера самого участника и не проверка его последующего успешного входа. Локальный диагностический сервер остановлен.

Первичное воспроизведение использовало локальный диагностический пример без Auth/API. После исправления проверена настоящая структура приложения в восьми E2E сценариях с вымышленными ответами Supabase; код диагностического сервера для этого не требуется.

На этапе диагностики было предложено точечно связать единственную карточку с существующим Auth и отделить привязку готовой карточки от самосоздания. После прямого разрешения Алексея оба серверных действия выполнены; источником Discord ID стала auth.identities, саморегистрация всем не включалась.

Точечный SQL сверил обе Discord identity, активность/блокировки и отсутствие конфликта; связал ровно одну карточку. Частная копия с конкретными ID сохранена только локально и не включается в git. Серверные auth_user_id и права после исправления подтверждены, фактический новый вход на устройстве участника ещё не подтверждён. Клиентская публикация требует разрешения на push/деплой.

В первоначальной диагностике выполнены10unit и визуальное воспроизведение, код ещё не менялся. Результаты последующего исправления и расширенные проверки приведены ниже.
