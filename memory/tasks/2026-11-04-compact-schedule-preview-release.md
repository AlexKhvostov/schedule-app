## Проверка обновления в Working

Создана одноразовая техническая Auth-сессия с отдельным memberId и правами profile/schedule, без root/admin. Плановая синхронизация Discord заблокировала эту искусственную карточку как отсутствующую на сервере; для короткой проверки восстановлены только её временные признаки и права. Глобальные проверки доступа и реальные аккаунты не менялись.

Источник постановки — штатная `apply_schedule_edit` с автором root в свободную ячейку 05.11, N50, 01:00 CET, линия 3; владелец — техническая карточка QZ. Независимый клиент авторизован как технический участник, подписан на настоящий закрытый канал Working. Событие записано в БД в 13:54:00.040756 UTC, получено клиентом в 13:54:00.226, ответ компактной RPC получен в 13:54:00.796. Примерно 185 мс до события и 755 мс до данных участка. Запрос содержал только 05.11/N50, вернул 87 слотов дня. Эти интервалы измерены относительно времени БД и часов клиента; это диагностический замер доставки/чтения, не покадровое измерение браузерной отрисовки.

Опубликованный браузер root без перезагрузки показал QZ, индикатор полной загрузки отсутствовал. Удаление выполнено обычной RPC через настоящий HTTP/Auth-клиент самого технического владельца; браузер другого аккаунта автоматически очистил ячейку и вернулся к 3399 меткам. Наблюдатель API к моменту удаления завершился по защитному таймеру; облачную задержку удаления отдельно не измеряли. Двухбраузерное удаление, замена, справочник и reconnect покрыты успешным CI.

Попытка поставить собственную SK в этой ячейке корректно показала «Лимит не выбран в кабинете»: у root N50 не выбран. Настройки реального аккаунта не менялись; для теста использована отдельная техническая карточка.

Тестовый слот удалён, технические member/auth/sessions/role удалены, временный файл учётных данных очищен. Итоговый контроль: все 3874 occupancy имеют исходный hash `1a84e6e90b0d535b178db0359b174e83`; ноябрь 3399. Полный штатный журнал тестовой постановки/снятия сохранён; импорт не повторялся. Реальные чужие смены не снимались.
