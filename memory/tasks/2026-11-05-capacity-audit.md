## Где и как настраивается

Меню администратора → «Настройки расписания» → «Ёмкость по часам CET». Слева Nitro/Regular и лимит, затем матрица чисел месяца31×24 или дней недели7×24. Значение1–6 — доступные места одновременно в каждый получас часа. Слоты дня = сумма24часов×2: постоянная глубина1 даёт48, глубина3 даёт144. Недельное и месячное правила повторяются; при включении обоих для одного часа берётся минимум. Выравнивание добавляет прозрачные строки, но не ёмкость. Сброс лимита —1 во все часы,48слотов; старая подпись «ночью2/64» была неверна.

## Исправления

- `VariantCapacityMap` хранит оба вида. Сетка/подписи линий, подсказки, клик и протяжка, аналитика выбирают карту конкретного вида. Все22пары проверены unit и SQL.
- Demo сохраняет отдельные ключи по виду; старый общий ключ используется только как начальное совместимое значение.
- Невозможность загрузить каталог/правила/флаги блокирует сетку и редактор до повтора; нет подстановки фиктивной ёмкости1. Ошибка каталога не кэшируется как успешное чтение.
- Админка ждёт успешного RPC, сохраняет только выбранную пару, не перезаписывает другие10лимитов. При ошибке сохраняет черновик. Во время записи редактор заблокирован. Выравнивание входит в общий Save вместе с матрицей/флагами. Смена раздела корректно инициализирует флаги.
- Выключенные недельные/месячные правила видны в редакторе со своими сохранёнными числами; предпросмотр явно относится к выбранной матрице. Раньше выключенное правило показывало базу и могло быть затёрто при редактировании.
- После уменьшения глубины старые верхние метки остаются видимыми, но лишние пустые места закрыты. Заполненность учитывает только открытые места, согласованно с аналитикой по получасам.
- «Мой календарь»/JPEG показывают записанные смены; свободные линии ёмкости туда не добавляются.

## Ограничения и состояние

Рабочие настройки ёмкости в Supabase не менялись и текущие числовые значения Working не выдаются за проверенные этим локальным прогоном. Исправление клиента не требует миграции ёмкости. Если выпускать вместе с активным приоритетом, его миграция по-прежнему обязательна.

Собственное сохранение сразу обновляет сетку; изменения другого администратора читаются после перезагрузки страницы, отдельная realtime-подписка не добавлялась. Одновременные сохранения одной пары используют прежнюю серверную механику без проверки версии; другие пары теперь не перезаписываются.

Первый полный прогон не стартовал из-за блокировки .next-e2e/trace параллельной работой. Успешный повтор выполнен на3189 с .next-e2e-capacity и временным конфигом в игнорируемом playwright-report. Первый расширенный тест записи обнаружил отсутствие E50 в кабинете тестового игрока: подготовка добавлена через UI, затем тест прошёл; производственные права не менялись.

Тестовые серверы завершены, локальная БД остановлена с backup. Публикация и рабочая база не затронуты. Следующий шаг — просмотр результата Алексеем; выпуск только по отдельному поручению.
