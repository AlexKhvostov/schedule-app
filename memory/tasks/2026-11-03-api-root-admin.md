# Root → API: управление подключениями

Обновлено: 2026-11-03 20:57 Europe/Minsk. Источник: поручение Алексея в чате. Только локально, без публикации и выдачи реальных облачных ключей.

Цель: отдельный пункт API в root-меню, создание индивидуальных ключей ботов, отзыв доступа и две инструкции в модальных окнах.

Критерии: сервер допускает управление только root; ключ генерируется криптографически и показывается один раз; в базе только хеш; список не раскрывает секреты; Demo не вызывает Supabase; RU/EN; проверены создание, инструкции, отзыв и запрет доступа другим ролям.

Рабочий выбор: название бота, контакт разработчика, примечание, срок действия и запросы/минуту. Единственное разрешение — schedule:read. Существующий ключ не редактируется и не восстанавливается: для замены создаётся новое подключение, старое отзывается. Секрет не сохраняется в браузерном хранилище.

## Результат

- [Экран](../../apps/web/src/v2/api/ApiAdmin.tsx) и отдельные стили; [слой данных](../../apps/web/src/data/externalApi.ts); root-menu → API, прямой маршрут `#root-api`.
- [Миграция](../../supabase/migrations/20261103173923_external_api_root_admin.sql): закрытые метаданные и аудит, root RPC создания/списка/отзыва. Секрет генерируется Web Crypto, на сервер уходит хеш; однократный показ, безопасный повтор при потерянном ответе.
- Поля: название обязательно, контакт/заметка необязательны, срок30/90/365 дней или бессрочно, квота1–600 (default60). Единственное разрешение schedule:read. Изменение существующих метаданных/квоты не включено; для замены создаётся новый ключ, старый отзывается.
- Две инструкции на RU/EN: владельцу и конкретному подключению. Последняя содержит URL выбранного сервера, имя, срок, квоту, пример, правила страниц и ошибок. При создании можно скопировать вместе с ключом, позднее только с placeholder.
- [Тесты data](../../apps/web/src/data/externalApi.test.ts), [E2E](../../apps/web/e2e/api-admin.spec.ts), [SQL contracts](../../supabase/tests/external_api_root_admin.sql). CI дополнен десятым SQL-набором.
