# Живые приоритеты Team50+

Обновлено: 2026-10-12 14:05 Europe/Minsk.
Источник требований: сообщения Алексея в этом чате 12 октября 2026.
Текущий этап: Working и тестовая ветка выпущены, полный облачный CI и реальная страница проверены; main не изменён.

## Цель и границы

Во вкладке «Приоритеты» заменить исторический снимок живым расчётом дистанций, добавить выбор Nitro/Regular, отображение ручного VIP и заявки на проверку расчёта. Переключатель50/100 по уточнению Алексея не нужен; оба лимита всегда участвуют в формуле. Расписание и автоматическая очередь в эту задачу не входят.

## Подтверждено пользователем

- Месячные очки: турниры лимита50 ×1 + турниры лимита100 ×2. Другие лимиты пока не учитываются.
- Шесть месяцев: старшие три ×0,5, младшие три ×1.
- Начало действия: февраль (август–январь), май (ноябрь–апрель), август (февраль–июль), ноябрь (май–октябрь). Это намеренно смещённые кварталы.
- Основную дисциплину заявляют вне приложения; выбор и автоматический штраф по ней не реализовывать. Последнее уточнение: расчёт всегда объединяет Nitro+Regular по50/100, выбор вида меняет только состав играющих этот вид участников и используемый VIP.
- Ручной VIP отдельно для Nitro/Regular закрепляет точное место: VIP3 занимает третью позицию, остальные заполняют свободные места по очкам. По умолчанию включён, переключатель меняет только отображение. Ручной VIP действует независимо от основной дисциплины. Уникальность нужна внутри каждого вида, такая серверная защита уже существует.
- Четыре числовые колонки: старшие три месяца50/100, младшие три месяца50/100. Каждая показывает уже взвешенные очки по коэффициенту лимита и периода; итог — их сумма. Подсказка раскрывает месяцы, исходные дистанции и коэффициенты; на телефоне нужна возможность открыть её касанием. Приложенный снимок — ориентир структуры, не источник живых данных.
- Фильтры: RedParty и Nitro50+ включены по умолчанию, наличие активной карточки; Winamax выбран и селект заблокирован. Другие фильтры пока не нужны.
- Первые семь дней месяца начала действия расчёт предварительный. С8-го числа он основной только при наличии минимум20 записей дистанции за последний месяц расчётного окна (июль для августа), а не за месяц начала действия. Пересчёт/проверка статуса не реже1-го и8-го числа каждого месяца и при изменении дистанций; основной расчёт тоже обновляется после исправлений, фиксация старых чисел не поручена.
- Пользователь согласился сохранять места при фильтрации: сначала распределять VIP и свободные места, затем фильтровать; номера могут иметь пропуски, пустые строки не рисовать.
- «Подать заявку» включает галочки возле строк, инструкцию и поле комментария; можно выбрать несколько людей. Заявка сохраняет подробный расчёт и исходные значения выбранных строк на момент отправки.
- Администратор видит автора, дату, адресатов, комментарий и полную детализацию в модальном окне. Может закрыть заявку с коротким ответом и удалить старую/неактуальную/случайную заявку (прямо разрешено пользователем в этой задаче).
- Обычные пользователи видят адресатов, дату и ответ администратора, без автора и исходного комментария.
- Заявка сама не исключает дисциплины и не изменяет числа. Администратор при необходимости исправляет дистанцию в существующем контроле; изменение дистанций инициирует обновление приоритетов.
- Страница должна быть компактной и читаемой на телефоне.

- `apps/web/src/v2/V2Priorities.tsx` показывает статический `prioritiesData.ts`, не считает загруженные данные.

- Нормализованные дистанции находятся в `distance_entries/distance_values`; административная выборка дистанций не предназначена для выдачи обычному игроку.
- Рабочее дерево содержит незавершённые изменения предыдущего этапа: MembersAdmin/model/tests, общие словари/CSS и документы. Сохранять их.

## Открытые вопросы

Существенные вопросы разрешены. Алексей выбрал отдельные галки «Вне рейтинга» Nitro/Regular. Исключённые идут вниз без номера, очки видны; положительный VIP одновременно с исключением не допускается.

Проверено дополнительно: saveMemberClub преобразует отрицательные VIP в0, схема запрещает отрицательные значения. Этот контракт сохранён: исключения теперь имеют отдельные галки, а−1 не используется.

Рабочие решения агента в рамках согласованных правил: сохранять точные половины очка без округления; при ничьих сортировать по нику, затем ID; публичный список заявок компактный, приватные детали выдаёт только административная RPC. Эти решения не являются новым глобальным предпочтением пользователя.

Рабочие решения реализации: точные половины очка, ничьи по нику и ID;20 логических записей distance_entries (не20 ячеек distance_values) Winamax последнего месяца с дистанцией50/100, суммарно по обоим видам. Чтение всегда пересчитывает актуальные данные и статус по серверному времени Europe/Minsk, поэтому1-е/8-е не зависят от фонового задания; открытая вкладка обновляет снимок по таймеру и после изменений. Приватные сведения заявок выдаются только административным RPC.
