## Реализация

- [Миграция](../../supabase/migrations/20261104125706_compact_schedule_sync.sql): `load_schedule_snapshot`, уникальные владельцы, 6 полей слота, каталог видов/лимитов, точные участки и справочник без слотов. Один SQL-срез, без таблицы кэша. Скалярный JSON не обрезается Data API после 1000 строк; пределы 100000 слотов/16 MiB дают явную ошибку.
- [Данные и подписка](../../apps/web/src/data/scheduleSnapshot.ts): проверка целостности ответа, закрытый Broadcast с координатами. Служебный ID сообщения Realtime не переносится в запрос участка.
- [Объединение](../../apps/web/src/schedule/mergeScheduleSnapshot.ts): замена затронутого дня/kind, включая пустой ответ после удаления последней метки; соседние дни/лимиты сохраняются. Смена профиля обновляет отображение владельца, сохраняя столы каждого слота.
- [Очередь](../../apps/web/src/v2/schedule/scheduleSync.ts): объединение событий за 100 мс, одно чтение одновременно, события во время чтения не теряются; ожидание своих записей и защита от старых ответов. Ошибки фонового чтения повторяются через 2–15 секунд без очистки сетки.
- [Жизненный цикл](../../apps/web/src/v2/schedule/useScheduleMonth.ts): подписка до начального чтения, полный месяц после reconnect/focus; при недоступном канале резервный опрос видимой вкладки раз в 10 секунд. Полный месяц всех лимитов обоих видов; отдельный повторный запрос собственных слотов удалён из активного пути.
- Сохранён штатный `apply_schedule_edit` со всеми серверными проверками и журналом. Старый read-RPC остаётся совместимым с опубликованным клиентом.
