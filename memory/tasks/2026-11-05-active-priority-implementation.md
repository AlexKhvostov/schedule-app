## Итог реализации

- [Миграция](../../supabase/migrations/20261105102935_active_priority_selection.sql): одна закрытая RLS-таблица priority_settings, август2026 по умолчанию. set_active_priority — identity/admin.people/root/квартальная дата/ожидаемый счётчик под блокировкой. Счётчик защищает от конкурентной перезаписи, не хранит версии расчёта или историю.
- load_priority_view возвращает активный период при null, либо явный просматриваемый период, и отдельные activePeriod/activeRevision/canActivate. load_active_month_roster выбирает период сервером, затем вызывает прежнюю компактную проекцию. Старые RPC и формула сохранены.
- [data/activePriority](../../apps/web/src/data/activePriority.ts) — сохранение выбора и Demo; [LivePriorities](../../apps/web/src/v2/LivePriorities.tsx) — активный по умолчанию, временный просмотр, кнопка применения и постоянная подпись. [data/roster](../../apps/web/src/data/roster.ts) принимает null для активного источника и сохраняет условные ответы. [V2Schedule](../../apps/web/src/v2/V2Schedule.tsx) перестал вычислять период из месяца расписания.
- Общий период для Nitro/Regular; Core/исключения и живые очки прежние. В250 очков нет. Переход даты и ручное обновление не меняют активный выбор. При просмотре любого месяца используется общий выбор; исторические назначения не создаются. Слоты и часы не меняются.
- Уведомление между вкладками того же браузера сразу запускает обновление; между отдельными сессиями сохраняется опрос до30секунд/фокус. Новых фоновых сервисов нет.
