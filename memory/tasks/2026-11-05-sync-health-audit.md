## Подтверждённые пробелы

1. **Нет постоянного статуса свежести.** connected — локальная переменная, не состояние интерфейса. Ошибка обновления показывается один раз в серии отказов; тост исчезает через4,2с. Нет времени последней подтверждённой сверки. Существующее окно «Онлайн» показывает присутствие пользователей, а не здоровье синхронизации. [Toast](../../apps/web/src/v2/V2Toast.tsx#L34).
2. **После фоновой ошибки правки остаются разрешены.** failLoad сохраняет ready=true. UI вычисляет gridLoading и gridLoadError только для !ready; обработчики записи проверяют ready, а не свежесть. Это не обход серверных прав, но пользователь принимает решение по старым занятым/свободным местам. [Возврат состояния](../../apps/web/src/v2/schedule/useScheduleMonth.ts#L69), [проверка записи](../../apps/web/src/v2/schedule/useScheduleMutations.ts#L109).
3. **Подключение не доказывает свежесть.** При connected=true резервный таймер не перечитывает месяц. Нет серверной ревизии/периодической контрольной сверки на случай пропущенного события при формально живом канале. Status сводится к boolean; причина ошибки подписки не сохраняется. Тихий сетевой обрыв обнаруживается не мгновенно.
4. **Нет собственного предельного ожидания RPC.** Незавершённое чтение удерживает running=true, поэтому новые refresh не стартуют. Незавершённая запись удерживает очередь и блокирует последующее согласование. В loadScheduleSnapshot/applyScheduleEdit нет AbortSignal/срока ожидания; установленный PostgREST передаёт полученный signal в fetch, но код его не задаёт. Это потенциально длительное ожидание, а не утверждение, что любой сетевой сбой зависает навсегда.
5. **Смежные данные защищены неодинаково.** Ёмкость V2Shell читает только при старте/ручном повторе и меняет после собственного сохранения; чужое изменение ёмкости уже открытая сессия автоматически не увидит. Настройки клуба и мёртвое время подписаны отдельно, но не перечитываются обязательно при reconnect/focus. loadScheduleSettings игнорирует error и может преобразовать отсутствие ответа в значения по умолчанию. Для общей зелёной отметки одного канала занятости недостаточно. [Ёмкость](../../apps/web/src/v2/V2Shell.tsx#L198), [правила](../../apps/web/src/v2/schedule/useScheduleRules.ts#L33), [настройки](../../apps/web/src/data/scheduleSettings.ts#L118).
6. Начальное чтение при уже подключённом канале после ошибки не имеет внутреннего автоматического повтора ScheduleSync. Здесь уже есть явный экран ошибки/кнопка, поэтому это меньший пробел, чем скрытая устарелость готовой сетки.

## Рекомендуемое поведение — предложение, ещё не реализация

Небольшой индикатор рядом с часами/управлением матрицей, с текстом и иконкой, а не только цветом. В штатном состоянии не занимает отдельную строку. При проблеме дополнительно постоянная заметная полоса над сеткой, доступная на телефоне и для screen reader.

| Состояние | Текст/действие | Правки |
|---|---|---|
| Снимок и критичные правила сверены, канал работает | «Обновления онлайн»; детали последней полной проверки | Разрешены |
| Канал прерван, свежие чтения работают | «Резервное обновление каждые10секунд»; восстановление автоматически | Можно разрешать после успешной сверки всех критичных данных и в пределах согласованного срока свежести; серверные проверки остаются |
| Сеть отсутствует/чтение завершилось ошибкой/превышен срок ожидания | «Данные могут быть устаревшими. Восстанавливаем связь…» и время последней проверки | Новая постановка, снятие и замена заблокированы; просмотр старого снимка остаётся |
| Восстановление не удалось, например30–60с | «Не удалось восстановить обновления»; «Повторить подключение», затем «Обновить страницу» | Заблокированы до успешной сверки |
| Сессия истекла/доступ отозван | Понятное предложение войти заново/обратиться к администратору | Заблокированы; бесконечные сетевые повторы не помогут |

Числа15с для ожидания чтения и30–60с для усиленной подсказки — стартовое предложение, их нужно проверить по реальным задержкам. Не выдавать отсутствие новых событий за сбой: в спокойном расписании изменений может не быть. Зеленеть после успешного применения снимка/правил, а не сразу после SUBSCRIBED; частичное обновление одного дня не должно обновлять время полной сверки месяца.

Расширить существующий ScheduleSync: сохранить состояние канала, последнюю полную сверку, ошибки/попытки, состояние записи. Добавить ограниченное ожидание/отмену чтений, backoff с небольшим случайным разбросом и контрольное чтение независимо от канала. Для экономии нагрузки предпочтительна лёгкая серверная ревизия месяца и правил с полным чтением при расхождении; для первого этапа допустима редкая полная сверка видимой вкладки с оценкой нагрузки. После сна/возврата/смены месяца сначала синхронизировать критичные источники, затем возвращать правки. Добавить обновление ёмкости и строгую обработку ошибок правил, не заменять известные настройки выдуманным fallback.

**Сохранение меток нельзя слепо повторять по таймеру.** При потере ответа сервер мог уже выполнить действие. Нужен статус «Не удалось подтвердить сохранение», остановка новых правок и сверка результата; автоматический повтор записи допустим только с серверным ключом идемпотентности. Не перезагружать страницу самопроизвольно и не терять незавершённые действия. Кнопка обновления страницы — последний явный шаг пользователя.

Минимально полезный цельный этап: статус+постоянное предупреждение, свежесть/блокировка правок, сроки ожидания и сверка после восстановления, повторная загрузка критичных правил/ёмкости. Один декоративный значок или повторная реализация переподключения SDK проблему не закрывают.

### Предлагаемый интерфейс, ещё не внедрён

Постоянная небольшая кнопка статуса в панели расписания рядом с редактированием. Не смешивать с существующим «Онлайн», который показывает людей. На узком экране — значок с доступным названием и удобной областью нажатия; при проблеме короткий текст сохраняется. Цвет дополняет значок и текст.

| Состояние | Текст кнопки | Новые правки |
|---|---|---|
| Канал работает и критичные данные сверены | Актуально | По существующим правам |
| Первая загрузка, возврат из фона или восстановление | Проверяем… | Приостановлены до успешной сверки |
| Канал потерян, автоматически восстанавливаемся | Восстанавливаем… | Приостановлены |
| Нет подтверждённой актуальности / повтор не помог | Нет обновлений | Приостановлены; доступна кнопка восстановления |

Обычная доставка изменений при здоровом канале обновляет ячейки без уведомлений на каждое событие. Не превращать каждое служебное чтение в глобальное мигание и блокировку. Основания блокировки: известная потеря синхронизации, превышение срока контрольной сверки, возврат из фона, непроверенные новые правила/ёмкость, неопределённый результат записи.

Нажатие на статус раскрывает компактное объяснение: «Расписание обновляется автоматически», «Последняя полная проверка: 16:20», кнопка «Обновить данные». Время означает подтверждённую полную сверку критичных источников, а не последний heartbeat или отдельную метку. При первом посещении — одна короткая закрываемая подсказка у статуса: «Расписание обновляется автоматически. Если связь пропадёт, здесь появится предупреждение». Предложение не является обещанием абсолютной одновременности: каждую запись сервер всё равно проверяет.

При потере синхронизации — небольшая постоянная строка над таблицей: «Обновления приостановлены. Редактирование временно недоступно» и «Переподключить». Таблица остаётся доступна для просмотра, прокрутки и подсказок.

### Попытка поставить/снять метку

1. Пользователь в режиме редактирования нажимает ячейку или начинает выделение. Если свежесть не подтверждена, запись не отправляется и временная метка не появляется.
2. Рядом с местом действия открывается одна компактная карточка: «Не можем проверить актуальность расписания. Ставить и снимать метки пока нельзя» + «Переподключить». При известном отсутствии сети: «Нет подключения к интернету. После восстановления связи расписание обновится автоматически». На телефоне карточка размещается в пределах экрана с удобной кнопкой.
3. Если восстановление уже идёт, карточка сообщает «Связь восстановлена. Проверяем расписание…»; повторная кнопка показывает ожидание, а не запускает конкурирующие запросы. По истечении ограниченного ожидания снова доступен ручной повтор.
4. Успешно получены метки, ёмкость и правила: карточка меняется на «Расписание обновлено. Повторите действие» и затем закрывается. Правки снова доступны только тем, кому они разрешены.
5. Не переносить прежнюю попытку клика/выделения в автоматическую запись: занятость места могла измениться. Обычные запреты прав, прошлых слотов и ёмкости сохраняют свои причины; не предлагать переподключение как средство обхода прав.

Одного canEdit=false недостаточно: нынешний обработчик переведёт нажатие в просмотр без объяснения. Нужна отдельная причина блокировки и обработчик попытки изменения, а проверка свежести должна повторяться непосредственно перед постановкой операции в очередь и при подтверждении открытых диалогов. Не делать всю таблицу inert — это лишит пользователя объяснения и просмотра.

### Автовосстановление и возврат

При скрытии пометить необходимость сверки и отменить незавершённый жест выделения. При возвращении немедленно удерживать новые правки, запустить объединённую сверку месяца и критичных правил/ёмкости. Если канал жив, достаточно сверки, принудительно разрывать его не нужно. Если соединение потеряно — восстановить подписку и затем перечитать данные. Сохранить месяц, фильтры, масштаб, прокрутку, выбранного игрока и намерение редактировать. Самостоятельно не включать режим редактирования у того, кто только просматривал таблицу.

Фокус видимого окна учитывать как запасной сигнал, объединять близкие события и избегать повторного запроса после только что завершённой проверки. Ошибка оставляет старые данные видимыми с явным предупреждением. Кнопка «Переподключить» запускает восстановление канала при необходимости и полную сверку данных; одно подключение ещё не делает статус зелёным. При стойкой ошибке предложить «Обновить страницу» вторым действием, без самопроизвольной перезагрузки.

Неопределённое сохранение обрабатывается отдельно: «Не удалось подтвердить сохранение. Проверяем результат». Не обещать, что метка не записана, не повторять запрос вслепую. До разрешения результата блокировать новые правки. Просмотр последнего снимка при живом HTTP, но сломанной доставке событий допустим с предупреждением; для первого этапа редактирование остаётся закрытым до восстановления синхронизации.

### Критерии будущей реализации

Проверить в E2E: обрыв канала при работающем HTTP; отсутствие сети; зависшее чтение с конечным сроком; фон/сон и возврат; изменение меток и ёмкости из второй сессии во время фона; восстановление без перезагрузки; повторное нажатие без дублирования запроса; неизвестный результат записи; отмена жеста на скрытии; открытый до сбоя диалог; обычные права своего/чужого игрока, выключенная настройка act-as, прошлые/закрытые места. Отдельно осмотреть узкий экран, клавиатуру и тексты RU/EN.
