# Исправление P2 частичной обычной записи

Обновлено: 2026-10-12 04:02 Europe/Minsk. Источник: Алексей напомнил исправить P2 «Частичная запись считается успешной».

Цель: весь обычный жест расписания применяется одной строгой транзакцией; просроченный слот отклоняет весь диапазон, клиент не принимает частичную запись и не сообщает преждевременный успех.

Критерии: обычные постановка/снятие используют уже применённую apply_schedule_edit; нет fallback на частичные записи; очередь и конфликт с просрочиванием покрыты; web-регресс и SQL-откат проверены. Предыдущие локальные UI-изменения сохранены.

## Сделано

- [useScheduleMutations.ts](../../apps/web/src/v2/schedule/useScheduleMutations.ts) использует строгую `apply_schedule_edit` для всех жестов: обычной постановки, снятия, смешанного изменения и подтверждённой работы с чужими метками. Кисть и владелец захватываются при жесте; при снятии используются собственные слоты даже с выбранной чужой кистью.
- [slots.ts](../../apps/web/src/data/slots.ts): прежняя клиентская `applyOwnSlots` делегирует строгой RPC с пустым foreign, поэтому `placeSlot`/`removeSlot` также безопасны. Старый fallback на раздельные INSERT/DELETE удалён. Отсутствующая функция возвращает ошибку без частичной попытки.
- Сетка по-прежнему отображает предварительный слой сразу, но тост успеха появляется только после успешного ответа сервера. Ошибка снимает весь слой конкретной операции; другая успешно завершённая операция очереди остаётся. Новых текстов не добавлено — используются существующие RU/EN сообщения конфликта и ошибки записи.
- Новая миграция не нужна: строгая функция уже применена к Working 12 октября и не изменяется. Старые серверные RPC остаются для совместимости и внутренних вызовов строгой функции; новые клиентские жесты их не обходят. Исправлен именно текущий клиент, старые опубликованные версии ещё используют прежний путь до нового выпуска.
