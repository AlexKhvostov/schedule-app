## Критерии готовности

Раздел доступен из шапки активного пользователя и по прямому адресу; без входа/для неактивного профиля не открывается. Внутренние переходы, назад/вперёд, перезагрузка, RU/EN, темы и телефон работают. Модуль не импортирует логику расписания и не делает запросов к аналитике; будущие блоки явно обозначены, фиктивных данных и неработающих кнопок записи нет. Пройдены обязательные web-проверки и визуальная проверка; документация соответствует коду.

Повтор полного E2E идёт через отдельный Demo dev3186 и временную конфигурацию, сборка — `.next-dashboard-build`, чтобы не делить Next-кэш с другим процессом.

## Результат итерации

- `apps/web/src/analytics` — самостоятельная оболочка: Dashboard, меню, заголовок, PlannedPanel, одна конфигурация 8 маршрутов, CSS Modules, локальные RU/EN-словари. Данные, фильтры и реальные операции записи ещё не реализованы.
- Общая интеграция ограничена V2Shell, shellNavigation, ключом nav.dashboard и 22 строками адаптивной шапки v2.css. Обе группы регов выделены в отдельном разделе. Администрирование пока не добавлено.
- Прямые hash-ссылки, история, перезагрузка, возврат в расписание, активный/неактивный профиль, телефон 320–760px и десктоп проверены. Верхняя кнопка проверена на фактическую доступность клика на 10 ширинах.
- Проверенная копия upstream не изменилась (61 совпавшая контрольная сумма); импортов предметной логики расписания и вызовов API в analytics нет. Секреты/реальные данные не добавлялись, PHP/MySQL/Supabase не менялись этой задачей.

## Итог проверок и ограничения

`typecheck`, `lint`, production `build` успешны. Unit через Vitest threads: 287/287 (включая параллельную задачу), новые Dashboard 4/4. Повтор полного Demo E2E через dev3186: **99 passed, 2 skipped, 1 failed**. Все 5 Dashboard-сценариев прошли, включая мобильную шапку после исправления. Единственный сбой — `login-schedule-mark.spec.ts:1246`: ищет «Онлайн», тогда как параллельная задача уже показывает «На сайте». Сам сценарий не изменялся этой задачей.

`bundle:check` **не прошёл**: 260,7 KiB / бюджет260. Лимит не повышен. UI/словари Dashboard отсутствуют в начальных файлах manifest; точный вклад остальных изменений не изолирован. Общая версия не объявляется полностью готовой к выпуску. Следующая проверка после стабилизации параллельной работы: актуализированный тест присутствия и размер начального пакета, при необходимости обоснованная оптимизация загрузки.

IAB и Chrome не смогли инициализировать инструмент (kernel assets / os error3); просмотрены PNG Playwright обеих тем и мобильного/настольного вида. Результаты находятся в `apps/web/test-results/dashboard-shell-check`. 26 перезаписанных тестами tracked-изображений архивированы в `apps/web/test-results/dashboard-shell-artifacts` и восстановлены из сделанной до тестов копии. Чужие файлы и результаты календаря сохранены. Временные include Dashboard в tsconfig убраны с сохранением чужих настроек.
