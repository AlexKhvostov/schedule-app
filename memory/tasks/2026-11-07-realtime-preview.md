## Что изменилось

Один закрытый `app:changes` передаёт короткие уведомления о метках, конфигурации, справочнике, приоритетах и доступе. Клиент объединяет события и читает изменившиеся участки. Общие настройки кешируются по аккаунту; независимые периодические чтения месяца, оформления и списков убраны. После переподключения/возврата выполняется сверка версий.

Страховка — дополнительная проверка версий с интервалом 1–60 минут, исходно выключена, сохранено 5 минут. Выключение не отменяет начальную загрузку, события, восстановление и ручное обновление. Без страховки тихо потерянное последнее уведомление может оставаться незамеченным до следующего события/возврата/reconnect/ручной проверки.

Серверная запись сравнивает ожидаемые клетки, выполняется атомарно и хранит закрытую квитанцию UUID. При потере ответа клиент предлагает проверить ту же операцию без повторного изменения. Искусственный срок свежести 60 секунд и запрет только из-за отсутствия WebSocket убраны; реальные ошибки доступа/сверки и неизвестная запись продолжают блокировать новые правки.

Presence показывает только подключённых участников, объединяя вкладки. Имя/аватар/Discord берутся из существующих загрузок и передаются по каналу. История действий и SQL-пинги больше не используются новым клиентом. Старые таблицы/RPC/legacy-канал сохранены для совместимости.

## Особенности проверочного стенда

Первый Demo запуск случайно получил 8 workers из-за передачи аргументов через npm/PowerShell. Изолированный временный runner затем деградировал из-за generated trace-файлов в сканируемом Tailwind каталоге; собственные артефакты перенесены в ignored `supabase/.temp`, повтор стабилен. Приложение ради обхода этого сбоя не менялось.

Одновременный запуск typecheck с Next build увидел удаляемые generated types; последовательный повтор после сборки успешен. Все 43 исходных чужих файла восстановлены из проверенных копий, а не из HEAD. Их текущие незакоммиченные изменения сохраняются намеренно.

## Ограничения и следующий шаг

Длительный суточный прогон и нагрузочный тест на 20–200 реальных клиентах не выполнялись. Точная первопричина исходного отказа Supabase не доказана; сервис восстановлен разрешённым Restart, тариф Free сохранён. Новый клиент ещё не уменьшает нагрузку от пользователей старого production-клиента.

Дождаться финального Web CI, зафиксировать его фактический результат. После приёмки Алексеем — отдельное решение о переносе проверенного клиента в main. Preview использует рабочие данные: для экспериментов с метками применять локальный стенд. Откат Preview возможен обычным возвратом прежнего клиента без удаления добавочной схемы.
