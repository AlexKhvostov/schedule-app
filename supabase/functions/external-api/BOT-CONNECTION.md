# Подключение внешнего бота к RedParty

**Для нового клиента с опросом раз в3минуты:** подготовлен APIv2 с курсором и отдельным справочником
людей — [инструкция v2](V2-SYNC.md). Использовать после подтверждённого выпуска серверной миграции и
функции. Ниже остаётся действующийv1; его потребители продолжают работать. Версия выбирается URL,
отдельный ключ позволяет независимо отозвать конкретное подключение.

Это инструкция для стороннего разработчика. В ней нет секретов; её можно передавать вместе с
[OpenAPI-контрактом](openapi.json). Облачный endpoint опубликован3 ноября2026; индивидуальный ключ
выдаёт владелец отдельно через Root → API.

## Что вам передаст владелец RedParty

1. Адрес API и указание среды (тестовая/рабочая).
2. Индивидуальный ключ вида `rp_…`, дающий только чтение расписания.
3. Срок действия ключа и контакт для его замены/отзыва.

Рабочий адрес API:

```text
https://wvfllegshaqonqqpbtle.supabase.co/functions/v1/external-api/v1/schedule
```

Адрес проверен при выпуске3 ноября2026. Обычный локальный адрес —
`http://127.0.0.1:54321/functions/v1/external-api/v1/schedule`; он доступен только на компьютере с
запущенной локальной Supabase. `localhost` не позволит внешнему боту подключиться к компьютеру
владельца через интернет.

## Хранение ключа

Сохраните ключ как секрет сервера бота, например в переменной окружения `RP_API_KEY` или в разделе
Secrets используемого хостинга. Адрес храните отдельно, например `RP_SCHEDULE_API_URL`. Ключ не
должен попадать в исходный код, Git, клиентский JavaScript, логи или URL. Supabase project key,
пароль базы и Discord OAuth для этого подключения не нужны.

## Первый запрос

```http
GET /functions/v1/external-api/v1/schedule?date=2026-11-03&days=31&limit=50&variant=nitro
X-API-Key: rp_<полученный индивидуальный ключ>
```

`date` и `days` обязательны. Начальный день входит в число дней:3 = выбранный день и следующие два.
Максимум31 день, календарь `Europe/Madrid`. `limit` и `variant` необязательны; отсутствие означает
все лимиты/оба вида. Допустимые виды: `nitro`, `regular`. Рум первой версии — Winamax. `limit=0.50`
передавайте именно строкой `0.50`.

Каждый успешный ответ содержит не более1000 меток и блок:

```json
{
  "slots_count": 1000,
  "pagination": {
    "snapshot_id": "11111111-1111-4111-8111-111111111111",
    "expires_at": "2026-11-03T17:15:00Z",
    "page_size": 1000,
    "page_number": 1,
    "total_pages": 3,
    "total_slots": 2350,
    "cursor": "22222222-2222-4222-8222-222222222222",
    "has_more": true,
    "next_cursor": "33333333-3333-4333-8333-333333333333"
  }
}
```

Это фрагмент вымышленного ответа. Метки находятся в `days[].lines[].slots[]`. `slots_count` — число
меток только этой страницы, `total_slots` — всего в снимке. Поле `complete` из раннего
неопубликованного прототипа убрано: завершение определяется только `has_more`.

## Продолжение выгрузки

Пока `has_more=true`, делайте GET на тот же адрес с **единственным параметром** `cursor=next_cursor`
и тем же заголовком ключа:

```http
GET /functions/v1/external-api/v1/schedule?cursor=33333333-3333-4333-8333-333333333333
X-API-Key: rp_<тот же ключ>
```

Не добавляйте к курсору дату/число дней/фильтры: они уже сохранены в снимке. Не вычисляйте и не
изменяйте cursor. Каждый следующий ответ использует тот же `snapshot_id`, `generated_at`, параметры
и срок; `page_number` растёт. Когда `has_more=false`, `next_cursor=null` — выгрузка закончена. В
примере с2350 метками получится1000+1000+350.

На каждой странице присутствуют все даты диапазона; пустая `lines` означает отсутствие меток **на
этой странице**, а не во всём месяце. Накапливайте данные по `date`, затем `line.id`, затем
`slot.start`. Не заменяйте собранный день пустым массивом из следующей страницы. Один день и одна
линия могут продолжаться на нескольких страницах. Повтор той же страницы безопасен при объединении
по `slot.start`; `pagination.cursor` позволяет повторить и первую страницу.

В течение15 минут все страницы воспроизводят один снимок: состав меток, владельцы, ники, цвета и
настройка столов не меняются вслед за сайтом. Для свежего расписания начните новый запрос с
датой/числом дней. Не смешивайте страницы разных `snapshot_id`. После замены ключа нужно начать
новую выгрузку: курсоры привязаны к конкретной интеграции.

Минимальный алгоритм:

```text
запросить date + days + нужные фильтры
запомнить snapshot_id и ожидаемое total_slots
добавить метки страницы в результат по date + line.id + slot.start
пока has_more:
    запросить только next_cursor с тем же X-API-Key
    убедиться, что snapshot_id прежний
    добавить метки без дубликатов
проверить, что число уникальных меток равно total_slots
использовать полностью собранное расписание
```

## Ошибки и повтор запросов

| HTTP | Значение                                               | Действие бота                                                          |
| ---- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| 400  | Неверные параметры, смешивание cursor с фильтрами      | Исправить запрос                                                       |
| 401  | Ключ отсутствует, неверен, истёк или отозван           | Запросить у владельца действующий ключ; не повторять бесконечно        |
| 403  | Нет права `schedule:read`                              | Обратиться к владельцу                                                 |
| 410  | Снимок истёк/удалён либо cursor недоступен этому ключу | Отбросить частичную выгрузку и начать заново с date/days               |
| 429  | Частота запросов или число активных выгрузок превышены | Выждать число секунд из `Retry-After`, затем повторить тот же запрос   |
| 422  | Защитное ограничение объёма отдельной страницы/снимка  | Сузить диапазон/фильтры; если причина сохраняется — сообщить владельцу |
| 503  | Временная ошибка сервера/БД                            | Повторить с паузой; не трактовать как пустое расписание                |

Обычно ключ допускает60 запросов за календарную минуту; каждая страница и её повтор считаются
запросом. Не создавайте новую выгрузку вместо получения каждой следующей страницы. При потере ответа
повторяйте последний запрошенный cursor; если потерян самый первый ответ, новый запрос с датой
создаст новый снимок.

Часовые слоты по30 минут: `start` и `end` — HH:mm в Europe/Madrid, на дате родительского дня. Конец
не включён. `24:00` — полночь следующего дня. Обычно `time_resolution` отсутствует; при `ambiguous`,
`nonexistent` или `transition` не назначайте точное уведомление автоматически. Для обычного слота
используйте IANA-пояс, а не фиксированное UTC-смещение. ID Discord — строка, не преобразуйте его в
обычное JavaScript-число. Если ID равен null, доступно только имя. `owner.name` — серверный ник,
затем глобальное имя Discord, username или сохранённое отображаемое имя. Это сведения на момент
создания снимка, включая запросы за прошлые даты. `tables` — число столов или null, когда оно не
задано либо функция столов отключена. Линия содержит `variant`, строковый `limit` и `number` с1; рум
— Winamax, валюта — EUR.

Для сообщения об ошибке передайте владельцу `request_id`, код ошибки и параметры без ключа. Ключ не
прикладывайте к скриншотам и логам.
