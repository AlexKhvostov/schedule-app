# Discord и живые люди — статус

Зафиксировано **21 сентября 2026**. Это не план «как должно быть», а что уже работает. Статусы клуба: [decisions.md](decisions.md#статусы-в-клубе).

## Что есть снаружи

**Приложение Discord `Redparty`.** Одно приложение на два дела:

| Часть | Зачем | Что умеет сейчас |
|---|---|---|
| OAuth2 | кнопка «Войти через Discord» | ник, аватар, почта, Discord ID человека |
| Бот | список людей на сервере клуба | ник на сервере, роли, дата входа, кто бот |

Это не два разных продукта. Бот — вкладка того же приложения. Бот уже стоит на сервере клуба. Privileged intent **Server Members Intent** включён.

Вход просит только `identify` и `email`. Роли сервера вход **не** читает. Роли читает бот.

Redirect входа: `https://wvfllegshaqonqqpbtle.supabase.co/auth/v1/callback`.  
Локальный возврат: `http://localhost:5173/` и `http://localhost:3000/auth/callback`.

## Что лежит в Supabase

Проект **schedule-app**, регион EU, ref `wvfllegshaqonqqpbtle`.

**Схема и сид** (SQL уже применён):

- справочники: Winamax, бай-ины Expresso/Nitro 0,25–500 €, MTT, nitro/regular;
- ёмкость в сиде: день 1, ночь 2; **живой бой сейчас — все единицы**;
- таблицы людей: `members`, `profiles`, `identities`, `member_roles`;
- роли приложения: `member`, `admin`, `staff`, `root`;
- снимок Discord: `discord_guild`, `discord_members`;
- слоты: `occupancy` (живые записи с поля next);
- кабинет: `players`, `player_nicks`, `player_limits` (ник рума и лимиты Nitro/Regular).

**Секреты входа** (Authentication → Discord): Client ID и Client Secret приложения. Ими человек логинится.

**Секреты бота** (Edge Function Secrets, не в git и не в браузере):

- `DISCORD_BOT_TOKEN`
- `DISCORD_GUILD_ID`

**Функция** `discord-guild`: пункт **Сервер** в меню только у root; сама функция пускает admin или root. Снимает сервер через бота и **записывает снимок** в `discord_guild` + `discord_members`. Кнопка «Обновить» снова ходит в Discord.

**Функция** `notify-mark-removed`: после снятия чужой метки бот пишет в клубный канал — какая метка, слот, кто снял — и в личку обоим. «Заменили» в тексте нет: для канала это то же снятие. Нужна галка «Метку сняли» у Discord-бота. Канал в кабинете и в карточке участника: Discord (по умолчанию), Telegram, почта.

**Функция** `bot-send`: только Root шлёт сообщение от имени Discord- или Telegram-бота. Токен пишется на странице Root, в браузер не возвращается (`bot_secrets`).

Кабинет не ходит в Discord. Он клеит `identities.provider_uid` к `discord_members.discord_id` и показывает ник, аватар, роли. Куда бот пишет — поле `profiles.notify_channel`.

Админка **Участники** читает тот же снимок. По умолчанию у всех доступ **закрыт**, кроме уже открытых карточек. Фильтр списка по умолчанию — **«Участники и админы»**. Админ ставит **участник**, **админ** или **staff** — тогда создаётся карточка `members`. На каждого с сервера карточку заранее не плодим. Root этой выдачей не ставится и не снимается. Если человек потом войдёт через Discord, вход приклеится к этой карточке.

**Первый живой человек:** `lihach.ok`. Discord ID записан в `identities.provider_uid`. В `members` он `active`, роли **root + staff** (не member и не admin). Слоты уже пишутся в `occupancy`.

## Два списка — это нормально

| Список | Откуда | Кто там |
|---|---|---|
| Сервер Discord | таблица `discord_members`, кнопка «Обновить» | все, кто сейчас на сервере |
| Расписание | наша база | только кто вошёл и кого пустили |

Склейка — **Discord ID**. Наш внутренний `members.id` — другой. Discord можно сменить, участник тот же, если перепривяжем `identities`.

Права расписания живут только у нас:

- играют **участник** и **админ**;
- **staff** сопровождает, на сетке его нет;
- **root** — сервис, в списке людей последним.

Роль на сервере Discord — сигнал, не ключ от админки. SQL `is_staff()` = admin или root, не клубный staff.

## Что сознательно ещё не делаем

Не создаём карточку расписания на каждого с сервера. Токен бота в браузер не возвращаем — только запись с Root. Не берём роли сервера как право поставить слот. Пинг «твоя очередь заполнять месяц» ботом — [после MVP](fill-queue.md); рубильник уже есть в Root.
