# Discord и живые люди — статус

Зафиксировано **24 сентября 2026**. Это не план «как должно быть», а что уже работает. Права: [decisions.md](decisions.md#профиль-и-права) и [auth.md](auth.md). Боты: [decisions.md](decisions.md#боты).

## Что есть снаружи

**Приложение Discord `Redparty`.** Одно приложение на два дела:

| Часть | Зачем | Что умеет сейчас |
|---|---|---|
| OAuth2 | кнопка «Войти через Discord» | ник, аватар, почта, Discord ID человека |
| Бот | снимок сервера, канал клуба, лички | ник на сервере, роли, дата входа; снятие чужой метки в канал и в DM; ручная отправка только Root |

Это не два разных продукта. Бот — вкладка того же приложения. Бот уже стоит на сервере клуба. Privileged intent **Server Members Intent** включён.

Вход просит только `identify` и `email`. Роли сервера вход **не** читает. Роли читает бот.

Redirect входа: `https://wvfllegshaqonqqpbtle.supabase.co/auth/v1/callback`.  
Локальный возврат: `http://localhost:5173/` и `http://localhost:3000/auth/callback`.

## Что лежит в Supabase

Проект **schedule-app**, регион EU, ref `wvfllegshaqonqqpbtle`.

**Схема и сид** (SQL уже применён):

- справочники: Winamax, бай-ины Expresso/Nitro 0,25–500 €, MTT, nitro/regular;
- ёмкость в сиде: день 1, ночь 2; **живой бой сейчас — все единицы**;
- таблицы людей: `members`, `profiles`, `identities`, `member_roles`;
- доступ по ролям Discord: `app_permissions`, `discord_role_permissions`, `discord_role_schedule_limits`;
- снимок Discord: `discord_guild`, `discord_members`, `discord_guild_roles`;
- слоты: `occupancy` (живые записи с поля next);
- кабинет: `players`, `player_nicks`, `player_limits` (ник рума и лимиты Nitro/Regular).

**Секреты входа** (Authentication → Discord): Client ID и Client Secret приложения. Ими человек логинится.

**Секреты бота** (Edge Function Secrets, не в git и не в браузере):

- `DISCORD_BOT_TOKEN`
- `DISCORD_GUILD_ID`

**Функция** `discord-guild`: пункт **Сервер** в меню только у root; сама функция пускает того, у кого есть «Управление пользователями». Снимает сервер через бота и **записывает снимок** в `discord_guild`, `discord_members` и роли. Полный синк помечает вышедших и блокирует активный профиль без RedParty. Обрыв списка никого не блокирует. Кнопка «Обновить» снова ходит в Discord.

**Функция** `discord-member-check`: при входе точечно спрашивает одного человека. Ответ 404 — вышел, профиль блокируется. Ошибка Discord профиль не трогает.

**Функция** `notify-mark-removed`: после снятия или замены чужой метки бот пишет в клубный канал — какая метка, слот, кто снял — и в личку **владельцу и тому, кто снял**. В тексте нет слова «заменили»: для канала это то же снятие. Нужна галка «Метку сняли» у Discord-бота (`bot_settings.notify_mark_removed`, по умолчанию вкл) и канал `notice_chat`. Личка может не дойти, если человек закрыл DM от участников сервера; канал от этого не зависит. Канал человека в кабинете и в карточке участника: Discord (по умолчанию), Telegram, почта. Telegram и почта — выбор на будущее, живая доставка сейчас Discord.

**Функция** `bot-send`: только Root шлёт сообщение от имени Discord-бота (Telegram — карточка есть, живых сообщений нет). Токен пишется на странице Root, в браузер не возвращается (`bot_secrets` + RPC `set_bot_token`). Списка операторов в продукте нет.

Страница **Root**: у Discord и у Telegram по три карточки — настройки, автоуведомления, отправка. «Очередь заполнения» — только рубильник, бот ещё не тегает.

Кабинет не ходит в Discord. Он клеит `identities.provider_uid` к `discord_members.discord_id` и показывает ник, аватар, роли. Открывается только с галочкой «Профиль». Куда бот пишет — поле `profiles.notify_channel`. Пишет владелец и тот, у кого есть «Управление пользователями».

Админка **Пользователи** — профили, заявки, роли и свёрнутый слепок. Фильтр профилей: все, активные, заблокированные, ушли с сервера, root, боты. Галочки раздела стоят на роли Discord, не на старом флаге admin. На каждого с сервера карточку заранее не плодим. Root этой выдачей не ставится и не снимается.

**Первый живой человек:** `lihach.ok`. Discord ID записан в `identities.provider_uid`. В `members` он `active`, в сервисе это root. Слоты уже пишутся в `occupancy`.

## Два списка — это нормально

| Список | Откуда | Кто там |
|---|---|---|
| Сервер Discord | таблица `discord_members`, кнопка «Обновить» | все, кто сейчас на сервере |
| Расписание | наша база | только кто вошёл и кого пустили |

Склейка — **Discord ID**. Наш внутренний `members.id` — другой. Discord можно сменить, участник тот же, если перепривяжем `identities`.

Права живут на ролях слепка. Слот ставится, если у роли есть «Расписание» и нужный лимит. SQL `is_staff()` — это галочка «Управление пользователями». Root видит все разделы отдельно от ролей.

## Что сознательно ещё не делаем

Не создаём карточку на каждого с сервера. Токен бота в браузер не возвращаем — только запись с Root. Меню не обновляет галочки, пока вкладка открыта: сервер проверяет роль в момент действия. Пинг «твоя очередь заполнять месяц» ботом — [после MVP](fill-queue.md); рубильник уже есть в Root.
