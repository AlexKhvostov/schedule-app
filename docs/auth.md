# Вход и доступ

С улицы самостоятельно зарегистрироваться нельзя. Сначала человек должен быть на Discord-сервере клуба и иметь роль **RedParty**.

Дата сверки: **25 сентября 2026**. К чему не возвращаемся — [decisions.md](decisions.md#профиль-и-права). Среды запуска — [environments-and-architecture.md](environments-and-architecture.md).

## Две разные вещи

1. **Слепок Discord** — кто сейчас на сервере, ник, аватар, роли. Это справка. Выход с сервера слепок помечает «вышел» и **не стирает** анкету.
2. **Профиль клуба** — участник сервиса. Статус только **активен** или **заблокирован**. Рабочий список — профили, не весь сервер.

Права стоят на **роли Discord**. У человека есть роль — у него есть её галочки. Несколько ролей складываются. Новая роль с новыми галочками даёт их, как только роль появилась у человека и слепок обновился.

## Что происходит при входе

В реальной среде вход — Discord. Прямой запрос к Discord выполняется один раз после нового OAuth-входа. При восстановлении уже действующей сессии приложение не спрашивает Discord повторно: оно использует сохранённый слепок. Полный слепок всего сервера обновляется автоматически каждые 10 минут и вручную администратором.

В локальной development-сборке перед входом можно выбрать Demo. Это фейковые данные в браузере, не настоящий вход и не проверка серверных прав.

- Активный профиль с правом «Расписание» открывает **расписание**. Если права нет, открывается первый доступный рабочий раздел.
- Прямой адрес раздела (`#schedule`, `#cabinet`, админка) открывает его, только если право есть. Без права приложение выбирает первый доступный рабочий раздел; портал-главная в маршрутизации не участвует.
- Профиля нет, или он заблокирован — ворота заявки, не пустая сетка. Заявка на вход и на восстановление требует живую RedParty. Ручная блокировка заявку не открывает.
- Самосоздание профиля возможно только если клуб включил тумблер и роль RedParty есть. Иначе профиль заводит тот, у кого есть «Управление пользователями».

Выход с сервера или снятие RedParty блокирует активный профиль. Само доступ не возвращается. Root не блокируется. Неполный синк никого не выключает. Ручная блокировка при выходе не затирается.

## Галочки

| Галочка | Что открывает |
|---|---|
| Профиль | Кабинет. Без неё пункта нет |
| Расписание | Сетка. Плюс лимит роли: Nitro или Regular и бай-ин. Без лимита слот не ставится |
| Управление расписанием | Настройки поля. Свои слоты не даёт |
| Приоритеты | Таблица и заявки доступны активным пользователям с этой галочкой либо правом «Расписание». Приватные детали и обработка заявок требуют `admin.people`/root |
| Управление пользователями | Профили, заявки, роли |
| Dashboard | Аналитика: активный профиль и право `dashboard` от роли Discord; root — по общему исключению |
| Дистанции | Админ: контроль дистанций. Импорт CSV — только Root |

Сейчас по клубу: RedParty даёт профиль, роль 50+ даёт расписание и лимиты 50 и 100, Staff даёт людей, приоритеты, дистанции и управление расписанием. Это сид. Галочки можно переложить на другие роли в редакторе.

Меню снимает права в момент входа. Сервер при записи слота и при открытии приоритетов смотрит роль заново.

## Кабинет и root

Кабинет — под аватаром, только с правом «Профиль». Выход остаётся в кабинете.

Экран root — боты Discord и Telegram. Старые роли «участник / админ / staff» оттуда не раздаются. Root как человек видит все разделы и не блокируется. Это исключение владельца, не галочка на роли.

## Метка за другого игрока

Исправление 5 ноября 2026: миграция применена к Working, клиент опубликован в main/на redparty.ru; при `allow_act_as=true` активному участнику с правом «Расписание» разрешено читать только пары вида/лимита выбранных игроков через `effective_schedule_access`. Это устраняет ложный запрет клиента при выборе чужой кисти. При выключенной настройке остаются чтение собственных прав и исключение для `admin.people`/root. Анонимному, участнику без «Расписания» и заблокированному автору новое право чтения не предоставляется.

Правила сохранения не расширены: активность автора/получателя, доступ получателя, выбранный игровой лимит, разрешённый клубный лимит, непустая метка, время и открытый уровень проверяются прежними серверными функциями. Удаление/замена чужих меток по-прежнему требует отдельного разрешения. [Проверки и границы выпуска](../memory/tasks/2026-11-05-act-as-fix.md).


## Dashboard — право роли, 6 ноября 2026

Для раздела требуется активный профиль и отдельное право `dashboard`, выдаваемое через «Пользователи → Роли → выбранная роль → Dashboard». Root сохраняет доступ при активном профиле. Право «Расписание» или «Управление пользователями» само по себе доступ к Dashboard не даёт. Это заменяет правило первой оболочки от5ноября, допускавшее всех активных участников.

Серверный `member_access_context` вычисляет право через существующие назначения ролей; клиент использует его в общей проверке `canAccessDashboard` для меню, прямого адреса и отображения содержимого. Изменённые права подхватываются при следующем обновлении страницы/входе, как остальные права оболочки; мгновенный отзыв уже открытой вкладки здесь не добавлен. Каталог дополняет миграция `20261106002512_dashboard_role_permission.sql`, без автоматических назначений. Локально проверены выдача, отзыв, root, неактивность, запрет самостоятельной выдачи и ошибка сохранения в редакторе.

Это право раздела приложения, а не завершённая серверная защита аналитики: legacy PHP API остаётся публичным. Production-guard живого источника сохранён до проверки сессии и актуального права на стороне PHP, включая прямые запросы. Миграция этой задачи пока применена только к отдельной локальной тестовой базе; рабочие роли не изменены. [План и результаты](../memory/tasks/2026-11-06-dashboard-role-access.md).


6 ноября: повторный анонимный GET подтвердил200JSON, HTTPS и CORS*. Серверная защита PHP не появилась вместе с SSL. Локальный source-переключатель — инструмент разработки, не новая модель доступа. Production-guard в `resolveAnalyticsMode` и loader не разрешает live; его нельзя снимать до внедрения и проверки PHP-допуска. OAuth/cookies расписания в публичный PHP не отправляются.
