# Текущее состояние

Дата сверки: **26 сентября 2026**. Этот файл отвечает на вопрос «что уже работает сейчас». Детали решений находятся в [decisions.md](decisions.md), история крупных работ — в [work-log.md](work-log.md).

## Коротко

- Каноническое приложение — `apps/web`, Next.js 15 + React 19.
- Сайт автоматически публикуется Vercel после push в `main`.
- Текущая облачная база Supabase — **Working/Development**; отдельный чистый Production ещё не создан.
- В production-сборке вход только через Discord. Выбор Demo / Working / Production доступен только локально.
- Миграции и Edge Functions выкатываются отдельно от сайта.
- В Working уже есть интеграционные и загруженные рабочие данные, включая дистанции. Чистого Production с боевыми данными пока нет; отдельные production-backups сознательно отложены до его подготовки.

## Среды

| Среда | Состояние |
|---|---|
| Demo | Работает локально. Фейковые пользователи, общее сохраняемое расписание в браузере, сброс из настроек |
| Working/Development | Текущий Supabase, настоящий Discord OAuth, миграции и интеграционные проверки |
| Production | Заглушка в локальном выборе. Новый чистый Supabase-проект будет создан перед публичным запуском |

## Что уже реализовано

### Вход и Discord

- Без сессии приложение не ждёт удалённую проверку и сразу показывает вход.
- Новый OAuth-вход один раз точечно проверяет пользователя в Discord.
- Восстановленная активная сессия читает слепок из базы и не обращается к Discord индивидуально.
- Полный слепок сервера обновляется каждые 10 минут и вручную администратором.
- Уход с сервера или потеря RedParty блокирует профиль по результату полного успешного слепка; root не блокируется.

### Расписание

- Месяц загружается одной серверной выборкой.
- Свои метки ставятся и снимаются оптимистично: экран меняется сразу, при ошибке выполняется откат.
- Поддерживаются клик и протяжка в одной линии уровня.
- На компьютере админ может разрешить постоянное редактирование. На телефоне та же сетка сначала открывается в безопасном обзоре: масштаб пропорционально уменьшает клетки по горизонтали и вертикали, кнопки идут по ровным десяткам, pinch остаётся плавным, а редактирование доступно с 75% после явного нажатия карандаша; галка завершает правку и возвращает перемещение. Инструкция и мобильные инструменты стоят в полосе под сеткой и не перекрывают ячейки; fit показывает текущий процент и вписывает поле с запасом без горизонтальной прокрутки.
- На узком масштабе верхний таймлайн сохраняет только CET и подписывает час его началом (`0` вместо `0–1`); полный диапазон и местное время возвращаются при увеличении.
- Работа с чужими метками использует единое предупреждение: безопасное действие слева, опасное красное справа, отмена отдельно.
- Владельцы удалённых чужих меток уведомляются ботом.
- Demo-расписание сохраняется между тестовыми пользователями в одном браузере.

### Люди и данные

- Админский экран получает согласованный снимок через `admin_people_snapshot`.
- Расписание получает готовый справочник игроков через `schedule_player_directory`.
- Игровые профили и платёжные методы сохраняются атомарными RPC.
- Права строятся по Discord-ролям и проверяются сервером.
- Discord-снимок и клубная карточка остаются разными сущностями, связанными по Discord ID.
- Root импортирует дистанции с выбранным покер-румом (по умолчанию Winamax); свежий ник из выгрузки атомарно становится текущим ником игрока и помечается в истории как системное обновление.
- Внизу Root-импорта есть отдельный предварительный просмотр исторического CSV с четырьмя строками шапки: выбор рума и Nitro/Regular, нормализация ID вида `101,00`, проверка связей и атомарная запись всего файла. Строки без ID дистанции пропускаются; совпадающие срезы не перезаписываются.
- Серверные изменения истории ников и RPC исторического импорта применены к Working Supabase 25 сентября 2026; сами исторические дистанции пользователь записывает только после проверки предпросмотра.
- «Контроль дистанций» строится от всех активных играющих участников: человек без записей за выбранный месяц остаётся в списке с нулями. Администратор раскрывает участника и через одно компактное модальное окно добавляет новый part или редактирует комментарий и значения существующего part; на desktop реквизиты и лимиты собраны в плотные строки, на телефоне — в две колонки.
- На контроле доступны покер-рум, поиск по никам и ID, сортировка по ID дистанции и дате изменения, фильтры наличия ID и дистанции. В строке видны ID дистанции и последняя дата изменения.
- CSV повторяет текущий отфильтрованный просмотр, включает нулевых участников, даты создания/изменения и сохраняет длинные ID без округления Excel; пользовательский текст защищён от интерпретации как формула.
- Дистанции нормализованы: `distance_entries` хранит характеристики part, `distance_values` — ненулевые значения по лимитам, `distance_batches` — операцию импорта или ручной записи. Legacy-таблица `distances` временно сохранена для отката.
- Demo содержит безопасные дистанции с заполненным и нулевым участником; ручное создание и редактирование работают в памяти Demo-сессии без обращения к Supabase.
- Ошибка загрузки контроля показывается отдельным блоком с причиной и повтором, а форма заранее объясняет, какой ID или количество турниров ещё нужно заполнить.

### Интерфейс и скорость

- На старте показывается экран проверки входа вместо пустого фона.
- Первый серверный и клиентский кадр одинаковы: Demo-сессия восстанавливается после гидратации без React hydration warning.
- Короткие системные уведомления появляются сверху под шапкой и не перекрывают мобильный рабочий блок расписания.
- Главная работает как пользовательский портал: объясняет возможности сервиса и даёт доступные по роли переходы в кабинет, расписание и приоритеты; будущая личная дистанция явно отмечена как ещё не доступная. Вернуться на главную можно по логотипу RP / Red Party, отдельного пункта «Главная» в меню нет.
- Большие разделы загружаются по требованию.
- Фон зависит от темы и не использует старую пятнистую картинку.
- Шрифты находятся в проекте и не зависят от внешнего сервиса.
- RU и EN поддерживаются через общие словари.

## Что намеренно ещё не сделано

- Отдельный Supabase Production и полноценный Staging.
- Автоматический деплой миграций и Edge Functions.
- Production backup/PITR и проверка восстановления.
- Автоматическая очередь заполнения месяца.
- Telegram- и email-доставка уведомлений.
- Реальное переключение личности пользователя в рабочей базе; Demo остаётся локальным UI-инструментом.

## Важные ограничения

- Demo проверяет интерфейс и предметную логику, но не доказывает корректность RLS, миграций, OAuth или Edge Functions.
- Открытый интерфейс может узнать об отзыве Discord-доступа с задержкой до следующего полного слепка; серверные проверки остаются обязательными.
- Vercel публикует сайт автоматически, но не обновляет Supabase.
- Документы `schedule-now.md` и `sandbox.md` — исторические снимки и могут содержать старые формулировки.
