# Текущее состояние

Дата сверки: **25 сентября 2026**. Этот файл отвечает на вопрос «что уже работает сейчас». Детали решений находятся в [decisions.md](decisions.md), история крупных работ — в [work-log.md](work-log.md).

## Коротко

- Каноническое приложение — `apps/web`, Next.js 15 + React 19.
- Сайт автоматически публикуется Vercel после push в `main`.
- Текущая облачная база Supabase — **Working/Development**; отдельный чистый Production ещё не создан.
- В production-сборке вход только через Discord. Выбор Demo / Working / Production доступен только локально.
- Миграции и Edge Functions выкатываются отдельно от сайта.
- Живых пользовательских данных пока нет; отдельные backups сознательно отложены до подготовки Production.

## Среды

| Среда | Состояние |
|---|---|
| Demo | Работает локально. Фейковые пользователи, общее сохраняемое расписание в браузере, сброс из настроек |
| Working/Development | Текущий Supabase, настоящий Discord OAuth, миграции и интеграционные проверки |
| Production | Заглушка в локальном выборе. Новый чистый Supabase-проект будет создан перед публичным запуском |

## Что уже реализовано

### Вход и Discord

- Без сессии приложение не ждёт удалённую проверку и сразу показывает вход.
- Новый OAuth-вход один раз точечно проверяет пользователя в Discord.
- Восстановленная активная сессия читает слепок из базы и не обращается к Discord индивидуально.
- Полный слепок сервера обновляется каждые 10 минут и вручную администратором.
- Уход с сервера или потеря RedParty блокирует профиль по результату полного успешного слепка; root не блокируется.

### Расписание

- Месяц загружается одной серверной выборкой.
- Свои метки ставятся и снимаются оптимистично: экран меняется сразу, при ошибке выполняется откат.
- Поддерживаются клик и протяжка в одной линии уровня.
- Работа с чужими метками использует единое предупреждение: безопасное действие слева, опасное красное справа, отмена отдельно.
- Владельцы удалённых чужих меток уведомляются ботом.
- Demo-расписание сохраняется между тестовыми пользователями в одном браузере.

### Люди и данные

- Админский экран получает согласованный снимок через `admin_people_snapshot`.
- Расписание получает готовый справочник игроков через `schedule_player_directory`.
- Игровые профили и платёжные методы сохраняются атомарными RPC.
- Права строятся по Discord-ролям и проверяются сервером.
- Discord-снимок и клубная карточка остаются разными сущностями, связанными по Discord ID.

### Интерфейс и скорость

- На старте показывается экран проверки входа вместо пустого фона.
- Большие разделы загружаются по требованию.
- Фон зависит от темы и не использует старую пятнистую картинку.
- Шрифты находятся в проекте и не зависят от внешнего сервиса.
- RU и EN поддерживаются через общие словари.

## Что намеренно ещё не сделано

- Отдельный Supabase Production и полноценный Staging.
- Автоматический деплой миграций и Edge Functions.
- Production backup/PITR и проверка восстановления.
- Автоматическая очередь заполнения месяца.
- Telegram- и email-доставка уведомлений.
- Реальное переключение личности пользователя в рабочей базе; Demo остаётся локальным UI-инструментом.

## Важные ограничения

- Demo проверяет интерфейс и предметную логику, но не доказывает корректность RLS, миграций, OAuth или Edge Functions.
- Открытый интерфейс может узнать об отзыве Discord-доступа с задержкой до следующего полного слепка; серверные проверки остаются обязательными.
- Vercel публикует сайт автоматически, но не обновляет Supabase.
- Документы `schedule-now.md` и `sandbox.md` — исторические снимки и могут содержать старые формулировки.
