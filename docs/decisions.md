# Зафиксированные решения

Чтобы не открывать одни и те же споры. Если меняем правило — правим этот файл и то место, где оно живёт в продукте. Дата сверки: **25 сентября 2026**.

Это не журнал задач. Это договорённости.

Как вести файл:

- сюда попадает только принятое устойчивое решение, а не идея на обсуждении;
- если решение изменилось, старая строка исправляется или явно помечается заменённой — рядом не создаётся противоречащий дубль;
- одновременно обновляются дата сверки, тематическая спецификация и при необходимости [текущее состояние](current-state.md);
- завершённые работы перечисляются в [work-log.md](work-log.md), а не здесь;
- будущие планы остаются в MVP или отдельной спецификации и не описываются как уже работающие.

## Продукт и экран

| Решение | Зачем так |
|---|---|
| Канон экрана — издание **next**. Страницу Архив / classic из меню убрали | Один рабочий вид. Старые правила клетки остаются в [schedule-ux.md](schedule-ux.md) как запись, не как экран |
| Первоначальный интерфейс перенесён из `sandbox/ui` в `apps/web` теми же React-компонентами; дальнейшая разработка идёт только в `apps/web` | Не поддерживаем две расходящиеся реализации одного продукта |
| Живой продукт — **`apps/web`**. Локальная песочница не едет на Vercel | Иначе два сайта и два деплоя |
| UI-кит, Блоки и Сервер — внутри меню **Админка** у root, не в кабинете игрока. Кабинет — под аватаром | Игрок не видит лабораторию. Админ ведёт клуб, не кит |
| После входа без прямой ссылки открывается **главная** | Игрок без расписания не попадает на пустую сетку. Прямой адрес раздела по-прежнему открывает его, если право есть |
| Главная — приветствие и инфоблоки: активные профили, люди на сервере Discord, роли с расписанием. Ниже пустые **Новости** и **События** | Цифра профилей не считает заблокированных. Новости и события встанут в те же блоки, когда появятся |
| Цвета сетки — **токены темы** из UI-кита «Слоты», не старые hex classic | Один канон на Расписании и в ките |
| В реальных средах вход — **только Discord**. Локальная development-сборка сначала предлагает Demo, Working и заглушку Production | Google и почта в MVP не входят. Выбор среды — инструмент разработки и в опубликованный интерфейс не попадает |
| Сетка **30 минут**, канон **CET / Europe/Madrid**. МСК только показ | Клик и база в одном поясе. Второй пояс не вторая сетка |
| Бай-ины Winamax — **евро Expresso**. Nitro и Regular — разные виды, **свои** наборы лимитов | Можно играть 50 Nitro и 25 Regular. Один общий список бай-инов это ломает |
| Метка на сетке **необязательна**. Если задана — **уникальна** в клубе. Буквы система **не резервирует**, в том числе PL | Иначе главу клуба нельзя посадить на его настоящую метку |
| Интерфейс сразу **RU и EN**, тексты только в словарях | Новый экран = сразу обе локали |
| Галка клуба **«Разрешить удалять чужие метки»** по умолчанию **выкл**. Вкл: любой, кто красит поле, может **снять** чужую метку **в той же строке уровня** после окна согласия. Поставить свою — отдельным жестом в пустой слот | Иначе случайно сносят чужие смены. Свою снимают без предупреждения |
| Галка клуба **«Заменять чужие метки»** по умолчанию **выкл**. Вкл: протяжка по диапазону с чужими — сначала снимем их, затем поставим ваши, после **того же** окна согласия. Клик по чужой по-прежнему только снимает | Иначе протяжка молча затирает чужую смену. Постановка в занятое — отдельное правило, не путать со снятием |
| Снятие и замена чужой — **одно окно**. Слева всегда безопасное действие без затрагивания чужих, справа всегда красное действие с чужими, снизу отдельно «Отмена». Если безопасного действия нет, кнопка остаётся на месте неактивной. В списке: аватар, ники, метка и число слотов; уведомление ботом вынесено отдельно | Позиция и цвет опасного действия не должны меняться между одиночной меткой и диапазоном — так его труднее перепутать |
| После снятия или замены бот пишет: в **клубный канал** — какая метка, слот, кто снял; в **личку** — владельцу и тому, кто снял. В тексте нет слова «заменили»: для канала это то же снятие | Иначе непонятно, чью метку убрали. Ставил ли человек свою на это место — не важно |
| Галка клуба **«Работа со столами»** по умолчанию **выкл**. Вкл: в окне правки задают число столов, оно пишется в метку. Выкл — столы не на чипах, не в правке, не в карточке слота | Сейчас клуб столы не считает. Колонка в базе остаётся, продукт её не показывает |

## Среды разработки и запуска

| Решение | Зачем так |
|---|---|
| Сейчас используем Demo и текущую Working-базу. Production показан заглушкой и ещё не создан | Не называем тестовые записи настоящими пользовательскими данными |
| Demo полностью локален, позволяет выбрать фейкового пользователя и не обращается к Supabase. Расписание сохраняется в браузере и общее для всех тестовых пользователей; в настройках его можно сбросить | Можно проверить взаимодействие нескольких ролей, не теряя метки при смене пользователя, и затем вернуть повторяемое исходное состояние |
| Текущий Supabase — Development/Working и пока допускает редактирование | На нём проверяются миграции, Discord, серверные права и интеграции |
| Перед публичным запуском создаём новый чистый Production из миграций, а текущий проект оставляем Development/Staging | В настоящую базу не попадёт накопленный тестовый мусор |
| Среда выбирается только в локальной development-сборке. Опубликованная сборка привязана к одному проекту | Нельзя случайно переключить работающий продукт на другую базу |

Подробности и порядок запуска: [environments-and-architecture.md](environments-and-architecture.md).

## Профиль и права

Слепок Discord и профиль клуба — разные вещи. Права стоят на **роли Discord**, не на старых подписях «участник / админ / staff».

| Решение | Зачем так |
|---|---|
| Слепок кормит живые поля профиля (ник, аватар, роли) и **не удаляет** профиль, когда человек вышел | Иначе выход стирает анкету |
| Профиль — участник сервиса. Статус: **активен** или **заблокирован** | Список людей фильтруется по этому статусу и по живым ролям Discord |
| Галочки доступа стоят на роли. Человек получает права всех своих ролей | Новая роль с галочками даёт их, как только роль есть у человека и слепок обновился |
| Обязательная роль клуба — **RedParty**. Нет её или человек вышел с сервера — активный профиль блокируется. Сам доступ **не возвращается** | Вышедший не остаётся внутри. Вернуть может только тот, у кого есть «Управление пользователями» |
| Ручная блокировка при выходе не затирается. Неполный синк никого не блокирует | Обрыв Discord не должен выключить клуб |
| **Root** не блокируется и видит все разделы. Экран root **не раздаёт** старые роли | Владелец не запирает сам себя. Права не из старого флага admin |
| Кабинет открывается только с правом **«Профиль»** | Меню и сервер смотрят одну галочку |
| Сетка: право **«Расписание»** и лимит роли (Nitro/Regular и бай-ин). **«Управление расписанием»** свои слоты не даёт | Вести поле и играть — разные галочки |
| Заявка на вход и на восстановление требует живую роль RedParty. Самосоздание профиля — только если клуб включил тумблер и роль RedParty есть | С улицы и без роли клуб не открывается |
| SQL `is_staff()` теперь значит право **«Управление пользователями»**, не старый флаг admin | Имя в базе старое, смысл новый |

## Люди и Discord

| Решение | Зачем так |
|---|---|
| Вход — **Discord OAuth** (`identify` + `email`). Роли читает бот и пишет в слепок | Личность с Discord. Права — галочки на ролях этого слепка |
| Бот — **снимок** сервера в `discord_members`, не живой Discord на каждом экране | Список людей можно обновить кнопкой. Сайт в Discord на клик не ходит |
| Карточку расписания **не создаём на каждого** с сервера. Админ открывает человека из снимка | Иначе 150 пустых карточек. Склейка потом по Discord ID |
| Кисть admin/root за другого — **не смена аккаунта**. Кабинет и «Мой календарь» остаются своими. В списке кисти — только игроки | Красим чужую метку, не логинимся чужим лицом |
| Discord ID и ID в клубе (`public_code`) **в кабинете не показываем**. Админ видит их в карточке человека — **те же блоки, что кабинет**, плюс выделенные служебные поля | Игроку эти номера ни к чему. Поддержка ищет по ним в админке |
| Админская карточка человека — **тот же кабинет**. Анкета, метка, рум, лимиты и **канал уведомлений** те же. Служебное (доступ, Discord ID, ID в клубе, VIP, дистанции) видно дополнительно и выделено | Иначе два разных макета. Админ меняет, куда бот пишет, не спрашивая человека |
| `distance_ext_id` пишет только тот, у кого есть «Управление пользователями» (SQL `is_staff()`), **в кабинете не показываем** | Это ключ к выгрузкам рук, не поле анкеты |

## Сетка и столы

| Решение | Зачем так |
|---|---|
| Галка **Редактирование**. Без неё сетка только читается. **Двойной клик не используем** | Случайный клик не ставит метку. Двойной клик заставлял ждать |
| Левый клик + протяжка **в одной строке уровня**. Чужой лимит в этот получас — красная рамка и подсказка, ставить можно. Две свои метки на соседних уровнях одного лимита — можно | Один жест. Часы считаем по уникальному получасу |
| Метка на поле **сразу**, запись в базу следом. Ошибка — тост и откат. После своей успешной записи **месяц целиком не качаем**. Чужие изменения приходят realtime | Иначе метка мигает: старый снимок месяца затирает только что поставленное |
| `members.tables` / `occupancy.tables` — кисть и снимок **только если** включена галка **«Работа со столами»**. Сейчас выкл: число в базе может лежать, на экране его нет | Не водим мёртвое поле, пока клуб столы не считает |
| Подсказка слота: **дата, время CET/МСК, метка, Discord-ник на сервере, актуальный ник на Winamax**, и столы **если клуб их считает**. Без ID | Ники читаются сразу. Номера человека на сетке не нужны |
| Прошлое на сетке — серый **токен темы** (`--muted`) по целому дню и уровню, на сегодня — до красной линии «сейчас». Не красим каждую клетку скриптом | Дёшево. Светлая и тёмная тема сами |
| Линия «сейчас» в **Моём календаре** — только красная черта на строке этого дня, без пульса и кружка | Иначе линия прыгает на соседние дни |
| Живая ёмкость сейчас: **1 на всех часах и лимитах**. Старое «день 1 / ночь 2» в сиде не путать с боем | Пока клуб маленький, поле узкое |
| Окно **Игроки месяца**: ники и **часы на поле** по выбранным лимитам. Шапка одной строкой `50 €, ч`. Нет меток — прочерк `—`. Часы всегда с одним знаком (`4.0`). Метки и остаток — в «Моих часах». Staff нет. Галочка «готово» пока неактивна | Список хода, не личная статистика и не саппорт |
| Часы игрока — **уникальные получасы**. Две метки в 50·1 и 50·2 в один получас, плюс третья на другом лимите — всё равно **0.5 ч** | Иначе вертикаль и параллельные лимиты раздувают стаж |
| Аналитика: на **каждый выбранный лимит** свой часовой график и своя шкала заполнения месяца (занято / доступные слоты). Без горизонтальной прокрутки графика | Два лимита — два поля, не одна каша |
| Журнал `occupancy_events` пишется сам, храним **2 месяца**. **Экрана журнала нет** и сейчас не делаем | Сетка журнал не читает. История для разбора, не для игрока |

## Кабинет

| Решение | Зачем так |
|---|---|
| Блок «Игрок и рум»: слева Nitro/Regular со своими бай-инами, справа ник и история | Лимиты и ник — разные вещи, на одном руме |
| Игрок = человек + рум (`players`). Ник — **история**, не ключ. Лимиты — `player_limits` по варианту | Сменил ник — дистанции не переезжают. Nitro 50 и Regular 50 — две строки |
| Пока у человека нет лимитов рума — **не** подставляем 50. Новичок сам включает бай-ины. Ставить метку можно, только если роль даёт право «Расписание» и этот лимит | «Я играю эти бай-ины» и «мне можно ставить метку» — разные вещи |
| Профиль: **все увидят только имя**. Остальное — информативный блок для админов. Текст **один раз в шапке**, не на каждом поле | Не пугать игрока повторами. Админам нужны телефон, Telegram, другой контакт, город, день рождения, пояс |
| Куда бот пишет человеку: **Discord (по умолчанию)**, Telegram или почта. Меняет сам в кабинете и админ в карточке участника. Живая доставка сейчас — Discord (канал клуба и личка). Telegram и почта — канал на будущее | Иначе всем одна труба. Админу не надо просить человека зайти и переключить |
| После записи в базу — тост «Сохранено». Не записалось — ошибка. Тишина после «Сохранить» недопустима | Иначе кажется, что сохранилось, а после перезагрузки старое |
| Платёжные реквизиты живут в `payment_methods`. Один блок в кабинете и в админ-карточке. Видят владелец и тот, у кого есть «Управление пользователями» | Админу нужно видеть кошельки, как человек их завёл, и комментарий. Не настройка вида сетки |
| Вторая шкала часов на сетке — галка в шестерёнке расписания (браузер), не поле карточки человека | У каждого своя настройка вида. Часовой пояс в анкете остаётся: где человек живёт по времени |

## Боты

| Решение | Зачем так |
|---|---|
| Писать от имени бота может **только Root**. Списка операторов в продукте нет | Иначе любой админ шлёт в канал клуба |
| Токен — только запись (`bot_secrets` + RPC `set_bot_token`). В браузер не возвращается | Утечка токена = чужой бот |
| На странице Root у Discord и у Telegram **три карточки**: настройки, автоуведомления, отправка | Не мешать конфиг, рубильники и ручную отправку |
| Галка Discord «Метку сняли» по умолчанию **вкл**. Галка «очередь заполнения» — только рубильник, рассылки нет | Снятие уже живое. Автоматизацию очереди не начинали |
| Telegram-бот — карточка есть, живых сообщений ещё нет | Канал выбран заранее, бота подключим отдельно |
| Клубный канал Discord — поле `bot_settings.notice_chat` | Туда уходит снятие метки и ручная отправка Root |

## Очередь заполнения месяца

| Решение | Зачем так |
|---|---|
| **MVP:** список игроков на текущем лимите по приоритету. Система ход **не запирает**, бот не тегает | Люди сами смотрят порядок и ставят метки |
| **После MVP:** замок хода, «я закончил», пинг в Discord. Не закладывать автоматизацию в текущие живые таблицы | Сначала обкатать поле. Подробно: [fill-queue.md](fill-queue.md) |

## Дистанции

| Решение | Зачем так |
|---|---|
| Три экрана: Root **«Импорт дистанции»**, админ **«Контроль дистанций»**, у игрока позже **«Дистанция»** | Выгрузка, проверка и личный просмотр — разные задачи |
| Файл на админский экран не попадает. Цифры контроля — только из `distance_entries` + `distance_values` | Иначе админ правит CSV, а не базу |
| Пишет Root: CSV, рум (по умолчанию Winamax), месяц, part и комментарий, «Записать» (`save_distance_dump`). Поля «основная/корректировка» и пользовательский ярлык не применяются: дополнительная порция — следующий part | Одного номера part достаточно для основной выгрузки и досылов; два параллельных признака создавали неоднозначные записи |
| Тестовую заливку Root стирает «Очистить месяц» / «Очистить всю таблицу» (`clear_distance_rows`). Два нажатия. Расписание и люди не трогаются | Иначе тестовый импорт нельзя откатить |
| На строке снимок: `member_id` (если карточка есть), `discord_id`, `distance_ext_id`, игровой ник `game_nick` | Discord или ID дистанции потом сменятся — история останется. Сортировка по игровому нику не требует CSV |
| Последний непустой ник игрока в импортируемой выгрузке — авторитетный текущий ник на выбранном руме. При успешной записи нового среза изменившийся ник добавляется в `player_nicks` с источником `distance` и месяцем выгрузки; ручные записи имеют источник `manual` | Кабинет показывает одну историю, но цветом и подписью отличает действие человека от системного уточнения по фактической дистанции |
| Исторический широкий CSV импортируется отдельным блоком Root: четыре строки шапки (месяц, part, лимит, название), отдельный выбор Nitro/Regular и рума, просмотр людей и связей до записи. Обязателен только ID дистанции; суффикс `,00` удаляется, строка без ID пропускается. Весь файл пишет одна RPC `save_historical_distance_dump`; конфликты пропускаются без UPDATE | Историческая матрица — другой формат, её не маскируем под текущую месячную выгрузку. Одна транзакция не оставляет половину истории при ошибке, а `ON CONFLICT DO NOTHING` защищает уже загруженный август |
| Контроль начинается со всех активных играющих `members`, а не с фактов дистанции. Нет записи — участник виден с нулями; записи без найденной карточки остаются отдельными сиротскими строками | Администратор может внести первый part любому участнику и при этом не теряет несвязанные исторические данные |
| Создание и редактирование выполняются одним модальным окном. При создании доступны рум, месяц, Nitro/Regular, part, комментарий и лимиты; при редактировании реквизиты заблокированы, меняются комментарий и значения | Структурные поля не должны случайно переносить запись в другой период; одна форма показывает, кому и что записывается |
| Логическая запись отделена от значений: `distance_entries` содержит участника, рум, месяц, вид, part, комментарий и аудит; `distance_values` — положительные значения по лимитам; `distance_batches` группирует операцию | Комментарий и реквизиты не дублируются на каждом лимите, один лимит обновляется одной строкой, а импорт можно будет откатить по операции |
| CSV из «Контроля дистанций» повторяет текущий просмотр, включая участников без дистанции. Длинные числовые ID экспортируются как точный текст для Excel, пользовательские строки защищаются от CSV-formula injection | Выгрузка совпадает с видимым реестром и не повреждает Discord ID |
| В Demo контроль имеет отдельный безопасный снимок и сохраняет ручные изменения только в памяти вкладки; ошибка Working RPC никогда не превращается в «пустой месяц», а показывается явно | Demo должен проверять весь интерфейс без записи в базу, а администратор не должен путать сбой сервера с отсутствием дистанций |

## База и перенос

| Решение | Зачем так |
|---|---|
| Одна Postgres в одном проекте Supabase (EU). Не несколько баз | Discord — внешний сервис. Auth — схема того же проекта |
| Новый рум или бай-ин — **новая строка** справочника, не новая таблица | PokerStars / GGPoker уже могут быть строками `rooms`, виды расписания пока только у Winamax |
| Git — только по согласованию | История репозитория — решение менеджера, не автопилот |

## Что сознательно не делаем сейчас

Не открывать эти темы, пока сами не скажем «делаем»:

- автоматизация очереди (замок, «я закончил», тег в Discord);
- экран журнала постановок;
- страница «Дистанция» у игрока (админский контроль и Root-импорт уже есть);
- Google-вход (кнопки на экране входа нет; привязка в кабинете — позже);
- скрейпер «кто реально сел»;
- старый флаг `admin` в `member_roles` как ключ от разделов;
- живые тексты новостей и событий на главной;
- Discord Activity, свой домен, pinch-zoom сетки (отдалить месяц на телефоне).
