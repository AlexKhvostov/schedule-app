# Зафиксированные решения

Чтобы не открывать одни и те же споры. Если меняем правило — правим этот файл и то место, где оно живёт в продукте. Дата сверки: **22 сентября 2026**.

Это не журнал задач. Это договорённости.

---

## Продукт и экран

| Решение | Зачем так |
|---|---|
| Канон экрана — издание **next**. Страницу Архив / classic из меню убрали | Один рабочий вид. Старые правила клетки остаются в [schedule-ux.md](schedule-ux.md) как запись, не как экран |
| Песочница `sandbox/ui` едет в бой **теми же React-компонентами**, не новой отрисовкой | Вид уже собран. Next.js — рамка сайта, не второй макет |
| Живой продукт — **`apps/web`**. Локальная песочница не едет на Vercel | Иначе два сайта и два деплоя |
| UI-кит, Блоки и Сервер — внутри меню **Админка** у root, не в кабинете игрока. Кабинет — под аватаром | Игрок не видит лабораторию. Админ ведёт клуб, не кит |
| Цвета сетки — **токены темы** из UI-кита «Слоты», не старые hex classic | Один канон на Расписании и в ките |
| На экране входа продукта — **только Discord** | Google и почта в MVP не входят. Демо-кнопки макета убраны |
| Сетка **30 минут**, канон **CET / Europe/Madrid**. МСК только показ | Клик и база в одном поясе. Второй пояс не вторая сетка |
| Бай-ины Winamax — **евро Expresso**. Nitro и Regular — разные виды, **свои** наборы лимитов | Можно играть 50 Nitro и 25 Regular. Один общий список бай-инов это ломает |
| Метка на сетке **необязательна**. Если задана — **уникальна** в клубе. Буквы система **не резервирует**, в том числе PL | Иначе главу клуба нельзя посадить на его настоящую метку |
| Интерфейс сразу **RU и EN**, тексты только в словарях | Новый экран = сразу обе локали |
| Галка клуба **«Разрешить удалять чужие метки»** по умолчанию **выкл**. Вкл: любой, кто красит поле, может **снять** чужую метку **в той же строке уровня** после окна согласия. Поставить свою — отдельным жестом в пустой слот | Иначе случайно сносят чужие смены. Свою снимают без предупреждения |
| Галка клуба **«Заменять чужие метки»** по умолчанию **выкл**. Вкл: протяжка по диапазону с чужими — сначала снимем их, затем поставим ваши, после **того же** окна согласия. Клик по чужой по-прежнему только снимает | Иначе протяжка молча затирает чужую смену. Постановка в занятое — отдельное правило, не путать со снятием |
| Снятие и замена чужой — **одно окно**, меняются шапка и кнопка. В окне: чип метки, аватар, ник Discord, ник Winamax, слот, схема «снимем → пусто или ваша → напишем» | Два разных макета путают. Человек должен уверенно подтвердить |
| После снятия или замены бот пишет: в **клубный канал** — какая метка, слот, кто снял; в **личку** — владельцу и тому, кто снял. В тексте нет слова «заменили»: для канала это то же снятие | Иначе непонятно, чью метку убрали. Ставил ли человек свою на это место — не важно |
| Галка клуба **«Работа со столами»** по умолчанию **выкл**. Вкл: в окне правки задают число столов, оно пишется в метку. Выкл — столы не на чипах, не в правке, не в карточке слота | Сейчас клуб столы не считает. Колонка в базе остаётся, продукт её не показывает |

## Статусы в клубе

Не путать **статус в группе**, **права сервиса** и SQL-функцию `is_staff()`.

| Решение | Зачем так |
|---|---|
| **Закрыт** — нет доступа или бан. Это не участник | Фильтр игроков их не показывает |
| **Участник** — играет по сетке | Игрок клуба |
| **Админ** — тоже играет, просто с правами. Все админы — участники | Не отдельная каста. Фильтр «участники и админы» = игроки |
| **Staff** — сопровождает и **не играет**: орги, саппорт, таблицы | Их нет в сетке и в «Игроках месяца». Только админский список людей |
| **Root** — права сервиса, не место в клубе. В списке людей **последним**, отдельная метка `root`. Обычно ещё статус staff | Владелец сервиса не участник. Не тащить в «и выше» |
| Отдельный флажок «это игрок?» пока не заводим: играют участник и админ, staff не играет | Статусы взаимоисключающие, кроме overlay `root` |
| Имя SQL `is_staff()` — **старое**: это admin **или** root (доступ к админке). Клубный статус `staff` туда **не** входит | Иначе орги получат админку без решения |
| Карточку заводим, когда админ открывает **участника, админа или staff**. На каждого с сервера заранее не плодим | Staff тоже нужен в системе (вход, кабинет), но не как игрок |
| Сетка, кисть «за другого», окно **Игроки месяца** — только участники и админы | Иначе саппорт попадает в ход месяца |

## Люди и Discord

| Решение | Зачем так |
|---|---|
| Вход — **Discord OAuth** (`identify` + `email`). Роли сервера вход не читает | Личность с Discord. Права — наша таблица |
| Бот — **снимок** сервера в `discord_members`, не живой Discord на каждом экране | Список людей можно обновить кнопкой. Сайт в Discord на клик не ходит |
| Карточку расписания **не создаём на каждого** с сервера. Админ открывает человека из снимка | Иначе 150 пустых карточек. Склейка потом по Discord ID |
| Кисть admin/root за другого — **не смена аккаунта**. Кабинет и «Мой календарь» остаются своими. В списке кисти — только игроки | Красим чужую метку, не логинимся чужим лицом |
| Discord ID и ID в клубе (`public_code`) **в кабинете не показываем**. Админ видит их в карточке человека — **те же блоки, что кабинет**, плюс выделенные служебные поля | Игроку эти номера ни к чему. Поддержка ищет по ним в админке |
| Админская карточка человека — **тот же кабинет**. Анкета, метка, рум, лимиты и **канал уведомлений** те же. Служебное (доступ, Discord ID, ID в клубе, VIP, дистанции) видно дополнительно и выделено | Иначе два разных макета. Админ меняет, куда бот пишет, не спрашивая человека |
| `distance_ext_id` пишет только тот, у кого SQL `is_staff()` (admin/root), **в кабинете не показываем** | Это ключ к выгрузкам рук, не поле анкеты |

## Сетка и столы

| Решение | Зачем так |
|---|---|
| Галка **Редактирование**. Без неё сетка только читается. **Двойной клик не используем** | Случайный клик не ставит метку. Двойной клик заставлял ждать |
| Левый клик + протяжка **в одной строке уровня**. Чужой лимит в этот получас — красная рамка и подсказка, ставить можно. Две свои метки на соседних уровнях одного лимита — можно | Один жест. Часы считаем по уникальному получасу |
| Метка на поле **сразу**, запись в базу следом. Ошибка — тост и откат. После своей успешной записи **месяц целиком не качаем**. Чужие изменения приходят realtime | Иначе метка мигает: старый снимок месяца затирает только что поставленное |
| `members.tables` / `occupancy.tables` — кисть и снимок **только если** включена галка **«Работа со столами»**. Сейчас выкл: число в базе может лежать, на экране его нет | Не водим мёртвое поле, пока клуб столы не считает |
| Подсказка слота: **дата, время CET/МСК, метка, Discord-ник на сервере, актуальный ник на Winamax**, и столы **если клуб их считает**. Без ID | Ники читаются сразу. Номера человека на сетке не нужны |
| Прошлое на сетке — серый **токен темы** (`--muted`) по целому дню и уровню, на сегодня — до красной линии «сейчас». Не красим каждую клетку скриптом | Дёшево. Светлая и тёмная тема сами |
| Линия «сейчас» в **Моём календаре** — только красная черта на строке этого дня, без пульса и кружка | Иначе линия прыгает на соседние дни |
| Живая ёмкость сейчас: **1 на всех часах и лимитах**. Старое «день 1 / ночь 2» в сиде не путать с боем | Пока клуб маленький, поле узкое |
| Окно **Игроки месяца**: ники и **часы на поле** по выбранным лимитам. Шапка одной строкой `50 €, ч`. Нет меток — прочерк `—`. Часы всегда с одним знаком (`4.0`). Метки и остаток — в «Моих часах». Staff нет. Галочка «готово» пока неактивна | Список хода, не личная статистика и не саппорт |
| Часы игрока — **уникальные получасы**. Две метки в 50·1 и 50·2 в один получас, плюс третья на другом лимите — всё равно **0.5 ч** | Иначе вертикаль и параллельные лимиты раздувают стаж |
| Аналитика: на **каждый выбранный лимит** свой часовой график и своя шкала заполнения месяца (занято / доступные слоты). Без горизонтальной прокрутки графика | Два лимита — два поля, не одна каша |
| Журнал `occupancy_events` пишется сам, храним **2 месяца**. **Экрана журнала нет** и сейчас не делаем | Сетка журнал не читает. История для разбора, не для игрока |

## Кабинет

| Решение | Зачем так |
|---|---|
| Блок «Игрок и рум»: слева Nitro/Regular со своими бай-инами, справа ник и история | Лимиты и ник — разные вещи, на одном руме |
| Игрок = человек + рум (`players`). Ник — **история**, не ключ. Лимиты — `player_limits` по варианту | Сменил ник — дистанции не переезжают. Nitro 50 и Regular 50 — две строки |
| Пока у человека нет лимитов рума — **не** подставляем 50. Новичок сам включает бай-ины. Доступ ставить метки выдаёт админ (`member_schedule_access`). Уже играющим доступ скопировали из их лимитов | Иначе нельзя выключить все лимиты и нельзя отделить «я играю» от «мне можно ставить метки» |
| Профиль: **все увидят только имя**. Остальное — информативный блок для админов. Текст **один раз в шапке**, не на каждом поле | Не пугать игрока повторами. Админам нужны телефон, Telegram, другой контакт, город, день рождения, пояс |
| Куда бот пишет человеку: **Discord (по умолчанию)**, Telegram или почта. Меняет сам в кабинете и админ в карточке участника. Живая доставка сейчас — Discord (канал клуба и личка). Telegram и почта — канал на будущее | Иначе всем одна труба. Админу не надо просить человека зайти и переключить |
| После записи в базу — тост «Сохранено». Не записалось — ошибка. Тишина после «Сохранить» недопустима | Иначе кажется, что сохранилось, а после перезагрузки старое |
| Платёжные реквизиты живут в `payment_methods`. Один блок в кабинете и в админ-карточке. Видят владелец и SQL-staff (admin/root) | Админу нужно видеть кошельки, как человек их завёл, и комментарий. Не настройка вида сетки |
| Вторая шкала часов на сетке — галка в шестерёнке расписания (браузер), не поле карточки человека | У каждого своя настройка вида. Часовой пояс в анкете остаётся: где человек живёт по времени |

## Боты

| Решение | Зачем так |
|---|---|
| Писать от имени бота может **только Root**. Списка операторов в продукте нет | Иначе любой админ шлёт в канал клуба |
| Токен — только запись (`bot_secrets` + RPC `set_bot_token`). В браузер не возвращается | Утечка токена = чужой бот |
| На странице Root у Discord и у Telegram **три карточки**: настройки, автоуведомления, отправка | Не мешать конфиг, рубильники и ручную отправку |
| Галка Discord «Метку сняли» по умолчанию **вкл**. Галка «очередь заполнения» — только рубильник, рассылки нет | Снятие уже живое. Автоматизацию очереди не начинали |
| Telegram-бот — карточка есть, живых сообщений ещё нет | Канал выбран заранее, бота подключим отдельно |
| Клубный канал Discord — поле `bot_settings.notice_chat` | Туда уходит снятие метки и ручная отправка Root |

## Очередь заполнения месяца

| Решение | Зачем так |
|---|---|
| **MVP:** список игроков на текущем лимите по приоритету. Система ход **не запирает**, бот не тегает | Люди сами смотрят порядок и ставят метки |
| **После MVP:** замок хода, «я закончил», пинг в Discord. Не закладывать автоматизацию в текущие живые таблицы | Сначала обкатать поле. Подробно: [fill-queue.md](fill-queue.md) |
| Импорт дампа дистанций и живой рейтинг — **не сейчас** | Сначала кабинет, слоты, люди |

## База и перенос

| Решение | Зачем так |
|---|---|
| Одна Postgres в одном проекте Supabase (EU). Не несколько баз | Discord — внешний сервис. Auth — схема того же проекта |
| Новый рум или бай-ин — **новая строка** справочника, не новая таблица | PokerStars / GGPoker уже могут быть строками `rooms`, виды расписания пока только у Winamax |
| Git — только по согласованию | История репозитория — решение менеджера, не автопилот |

## Что сознательно не делаем сейчас

Не открывать эти темы, пока сами не скажем «делаем»:

- автоматизация очереди (замок, «я закончил», тег в Discord);
- экран журнала постановок;
- импорт выгрузки рук / дамп дистанций;
- Google-вход (кнопки на экране входа нет; привязка в кабинете — позже);
- скрейпер «кто реально сел»;
- роли Discord как ключ от админки;
- Discord Activity, свой домен, pinch-zoom сетки (отдалить месяц на телефоне).
