# Модель данных

Центр — **участник**. «Человек» и «игрок» не живут отдельно: это анкета и ники на румах.

```
Участник
  ├── профиль (1:1)
  ├── привязки входа + кэш профиля Discord
  ├── роли (локальная таблица = источник прав)
  ├── статус в сообществе (тип: Training / RedParty)
  ├── метка сетки (2 символа, цвет фона, цвет шрифта)
  ├── платёжные реквизиты (несколько)
  ├── поручитель (ссылка на другого участника, только админка)
  ├── игроки (участник + рум)
  │     ├── история ников
  │     └── лимиты Nitro / Regular отдельно
  └── дистанции (участник + рум + месяц, не кабинетные лимиты)
```

## Участник

Кто в системе, кто логинится, кому слоты и доступы.

- внутренний id (uuid базы, не Discord и не для экрана);
- публичный код `public_code`: `RP-` и шесть знаков. Короткий код для поддержки и **карточки человека в админке** (служебное выделенное поле). В кабинете игроку не показываем. Не Discord ID. Сейчас шесть hex, чтобы не светить порядковый номер; «RP-104» из макета читается проще, но это уже счётчик людей;
- ID во внешнем сервисе дистанций (`distance_ext_id`): цифры, обычно 3–4. Админ заполняет в списке участников и в карточке человека. В кабинете не показываем. По нему склеиваем месячную выгрузку рук с карточкой клуба;
- статус заявки: ждёт апрув / активен / блок;
- статус в сообществе (**тип**): `Training` или `RedParty`. Это не роль и не доступ к сетке. Подпись на экране пока «тип», названия значений всегда английские;
- метка: два символа, **необязательна**; если задана — уникальна в клубе; цвет фона; цвет шрифта. Система буквы не резервирует (PL — обычная метка основателя, не служебный код);
- ручной **VIP-приоритет по виду**: отдельно Nitro и отдельно Regular. 1 — первый в списке этого вида, номер уникален внутри вида. Пусто — без VIP. Живой рейтинг и автоматизация очереди — после MVP, [fill-queue.md](fill-queue.md);
- поручитель: другой участник. Выпадающий список в админке, в кабинете нет;
- даты входа.

Роль ≠ статус заявки. Заявка — ждёт / активен / блок. **Статус в клубе** — закрыт / участник / админ / staff; **root** — не статус клуба, а права сервиса поверх.

Играют **участник и админ**. Staff сопровождает и на поле не ставится. Root в списке людей последним, обычно ещё staff, не участник и не админ. Подробно: [decisions.md](decisions.md#статусы-в-клубе).

Не путать клубный `staff` с SQL `is_staff()`: в базе это имя старое и значит **admin или root** (админка, чужая кисть, служебные поля). Клубный staff туда не входит.

## Профиль

Имя, контакты, день рождения, локация, **часовой пояс** (местное время человека: когда можно написать). Не смешивать с правами и никами румов. Показывать ли вторую шкалу часов на сетке — настройка вида расписания в браузере, не поле анкеты.

**Все увидят только имя.** Остальное — информативный блок для админов (телефон, Telegram, другой способ связи, город, страна, день рождения, пояс). На экране кабинета это пишем **один раз в шапке** блока, не повторяем на каждом поле.

Куда бот пишет человеку — `notify_channel`: Discord (по умолчанию), Telegram или почта. Меняет сам в кабинете и админ в карточке участника. Живая доставка сейчас Discord.

## Привязки входа

Discord, позже Google: провайдер + id у провайдера. Можно перепривязать Discord, участник тот же.

**Кэш с Discord при входе** (обновлять, если изменилось): аватар, username, отображаемое имя, ник на сервере группы и всё полезное из OAuth/гильдии. Хранить у привязки или карточке участника. Сервис показывает это из своей базы, не дёргая Discord на каждом экране.

## Роли

Источник прав — **наша** таблица. Сетка смотрит только её.

Четыре роли приложения: `member`, `admin`, `staff`, `root`.

- участник и админ — игроки (админ всегда ещё member);
- staff — сопровождение, не игрок;
- root — сервис поверх клубного статуса, не место в группе. Функция `set_discord_access` root не выдаёт и не снимает.

Обновление: при входе через Discord; опционально раз в сутки; позже бот пушит смену ролей к нам. Понизили роль у нас — доступ закрыт без повторного похода в Discord.

`is_staff()` в SQL — **admin или root**, не клубный статус staff. Это имя не переименовываем без нужды: на него завязаны RLS.

Роли только приложения (админ сайта) живут только у нас.

## Игрок и ник

**Игрок** = участник + рум, свой id навсегда. Дистанции этого рума висят на игроке. Слоты ссылаются на **участника и вид** (у вида уже есть рум).

На одном руме Nitro и Regular — разные наборы лимитов: можно играть 50 Nitro и 25 Regular. В кабинете слева виды и бай-ины, справа ник и история. Ник — текущая подпись плюс история, не ключ.

**Ник** — история подписей, не ключ сущности. Сегодня ник как на другом руме — меняем две подписи, дистанции с румов не переезжают.

В админке может выглядеть как матрица участник × румы.

## Платежи

Не «привязка входа». Таблица `payment_methods`: банк, USDT и т.д. Несколько на участника, один основной. Сюда не класть Telegram, документы, ники. Блок один: кабинет игрока и карточка человека у админа.

## Справочники игры

Чтобы не путать слова:

| Термин | Смысл | Сейчас |
|---|---|---|
| Формат | кэш или турнир | два значения, список расширяется |
| Вариант | какой турнир | nitro / regular; у кэша пусто |
| Лимит | 25, 50, 100… | справочник, можно привязать к руму |
| Рум | где играют | пока один, второй — новая строка |

**Вид расписания** = рум + лимит + формат + вариант. На него ссылаются слоты и ёмкость.

На **экране** фильтров песочницы слово «Вид» пока означает nitro / regular (в таблице выше это **вариант**). Полный вид (ещё рум и формат) в фильтре появится, когда подключим справочник. Не путать с подписью на кнопке.

## Ёмкость

Не занятость, а правила «сколько своих можно».

Сколько **уровней** открыто в этот час у лимита. Диапазон **1–6**. Считаем получасы: одна линия суток = 48 слотов; ночь глубины 2 даёт ещё 16, в дне 64.

В песочнице у лимита три слоя, которые можно править матрицами в админке:

- общее правило часов (в сиде: день **1**, ночь 22–06 **2**; **живая** ёмкость сейчас все единицы — клуб маленький);
- числа месяца (1–31);
- дни недели.

Число месяца и день недели — **разные** правила. Если оба заданы на один час, берём **минимум** (жёстче побеждает). Нет особого правила — общее. Как это выглядит на экране — [schedule-ux.md](schedule-ux.md).

Несколько меток в одном часе в базе: несколько записей занятости, на экране — несколько **линий уровня**, не excel-строки дня.

## Занятость (слоты)

Получас в каноническом поясе сетки (Испания). Запись: **участник + вид + начало слота + уровень**. Один человек может занять несколько мест в тот же получас (соседний уровень того же вида или другой лимит). Часы работы — уникальные получасы, не число меток.

На экране в клетке показываем **текущий ник игрока этого рума** (и ник Discord из кэша входа) — не устаревшую подпись из момента клика.

Число **столов на слоте** пишется в `occupancy.tables` в момент постановки и больше не меняется — **если** клуб включил «Работа со столами». Сейчас галка выкл: колонки в базе остаются, на сетке, в правке и в карточке слота числа нет. Когда снова включим: в окне правки плюс, минус или ввод сразу пишут последнее выбранное число в карточку (`members.tables`) — это только кисть по умолчанию для следующих меток, не правка уже стоящих.

Один человек может стоять в тот же получас на нескольких уровнях и видах: две линии 50 и ещё 100 — всё равно полчаса работы. Клетка вида полная, когда меток уже столько, сколько разрешила ёмкость.

Чужие на разных видах в одно время — можно.

## Дистанция

Факт: срез по лимиту — ID клуба (если карточка уже есть) + ID Discord + ID дистанции + рум + календарный месяц + Nitro/Regular + бай-ин + признак ввода + part + ярлык + игровой ник + комментарий + число рук.

Все три ID и игровой ник пишем в строку снимком: Discord, ID дистанции или ник потом могут смениться, история не затирается. Копить под участника можно по `member_id`, когда карточка появится.

Рум в строке сразу. Кабинетные лимиты рядом не стоят. Сумма по человеку и году считается запросом.

`entry_kind`: по умолчанию основной (`primary`); корректировка — отдельная строка, итог складывается. `part`: по умолчанию `1`; досыл или смена учёта — `2`, `3`, не затирая уже залитый кусок. Ярлык (`batch_label`) помечает пачку: тот же или новый, в уникальный ключ не входит.

Одинаковые срезы (рум + месяц + вид + лимит + признак + part + ID дистанции) повторно не пишутся. Импорт файла — экран Root. Админка «Контроль дистанций» показывает уже лежащие в базе строки и даёт их править. Просмотр «Дистанция» у игрока — отдельный экран, позже.

Приоритет из дистанций — отдельный этап, формула позже.

## Что сознательно не копируем из старых таблиц

Простыня всех колонок про человека; дистанции столбцами вправо; расписание как лист 48×31 в базе; доступ как десяток галок вместо ролей; ник как идентификатор игрока.
