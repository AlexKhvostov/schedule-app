# Аналитика Dashboard — отдельный модуль

Дата переноса: 5 ноября 2026. Статус: **исходники для последующей адаптации, не подключённая и не защищённая страница**. Алексей подтвердил этап «анализ и отдельная копия». Расписание, его навигация, Supabase и сборщик данных не изменены.

- `upstream/` — копия актуального Vue/PHP-модуля из `winamaxScraper/v2/analytics`.
- [Манифест](import-manifest.json) — состав, SHA-256 исходников и копии, исключения и изменения при переносе.
- [Разбор и план подключения](../../docs/analytics-dashboard.md) — базы, авторизация, риски и следующий этап.

Этот каталог не входит в сборку `apps/web`, не является npm workspace и не публикуется автоматически как страница. Слово `upstream` означает импортированные исходники. По последующему решению Алексея новый интерфейс пишется на React в самостоятельном модуле `apps/web/src/analytics`; PHP и MySQL сохраняются. `upstream` остаётся референсом, его не подключаем к сборке сайта. [План модульного переноса](../../docs/analytics-dashboard-plan.md).

## Что скопировано

Текущие `app/src`, конфигурация и lockfile Vue, PHP API, SQL-описания таблиц без выгрузок, тематические документы, Apache-конфигурация и исходные служебные скрипты. Для `.env.example` создан чистый шаблон: пароли и адрес базы пустые. Исходный каталог не изменён.

**Исключены:** настоящие `.env`, готовые `dist`/`hostland-upload`, зависимости `node_modules`, содержимое runtime-кэша, старый `ref` целиком. В `ref` обнаружен встроенный пароль базы; старый интерфейс и снимок игроков не нужны текущему приложению. Значения секретов в манифесте и документации не сохраняются.

## Ограничения запуска

Не размещать этот каталог как публичный сайт до реализации защиты. В импортированном PHP отсутствует общая проверка входа на отчётах, регах и заметках. Даже `/health` вызывает соединение с автоматическим созданием таблиц/индексов. **Не подключать рабочий `.env` для пробного просмотра.**

Для проверки только сборки интерфейса из `modules/analytics/upstream/app`:

```powershell
npm ci --ignore-scripts
npm run build
```

Команды не запускают PHP и не проверяют данные/формулы на настоящей базе. Переменные `VITE_*` попадают в браузерную сборку: секреты туда не помещать. Метрика не настроена; исходный код при включении счётчика активирует Webvisor, что требует отдельного решения для закрытой аналитики.

## Внешние зависимости исходного проекта

Исходный README описывает команды из корневого `package.json` **winamaxScraper**; в `schedule-app` эти команды не добавлены. `scripts/rebuild-player-hour.cjs` зависит от `dotenv`, `mysql2`, корневого `.env` и каталога `runtime` скрапера; он очищает и пересчитывает таблицы. Панель пересчёта читает runtime и журналы исходного проекта. Эти скрипты сохранены для анализа, **не адаптированы и не запускались**. Скрипты deploy также не запускать: они копируют `.env` в пакеты размещения и заменяют их содержимое.

PHP-launcher ссылается на управляемый runtime исходного проекта. Его путь после переноса не настроен; для будущего запуска нужен явно выбранный и проверенный `PHP_BIN`. Документы исходного проекта `docs/PHP_SECURITY.md` и `docs/DATA_POINTS_MAX.md` находятся за пределами импортируемого блока и не перенесены. Ссылки на них в импортированных Markdown заменены ссылкой на этот раздел; правила времени и плотности находятся в `upstream/docs/`. Полная схема и процесс сбора `tournament_snapshots` также остаются в проекте скрапера.

## Следующий этап

Первая React-оболочка уже создана локально в `apps/web/src/analytics`: меню, маршруты и области будущих блоков. Фильтры и «Очки за день» уже реализованы на синтетическом источнике; отдельная проверка реального PHP подтвердила контракт и выявила проблемы HTTPS/доступа/свежих агрегатов. Следующий этап — защищённое подключение по [плану](../../docs/analytics-dashboard-plan.md). До реального подключения определить серверную защиту PHP и роли чтения/записи. Vue используется только как образец; публичный iframe не применяется. Выявленные недочёты добавления/переноса/удаления регов внесены в критерии переноса; upstream остаётся неизменным.
